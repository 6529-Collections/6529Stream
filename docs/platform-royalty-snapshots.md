# PLATFORM_WORKS prepared royalty snapshots

This source increment extends the existing prepared snapshot path to collections
with an actual current PLATFORM_WORKS declaration. It adds no signing domain,
Artist operation, royalty preimage, snapshot layout, Manager selector or payment
route. Runtime and deployment-size acceptance remain pending.

RSR-ARTIST-ECONOMICS excludes declared artist-less collections from operation 15.
The Resolver owner still installs source terms and elects snapshot mode. Before
source admission or mode-2 collection SET, the fixed read worker authenticates
the Core-selected Artist address/runtime, actual consent mode 3, absence of an
accepted or nominated Artist, and the original declaration preimage. It joins
the full current Platform state with its declaration, contest and correction
reads. NONE and DISMISSED allow admission; OPEN, SUSTAINED, unknown state and any
corrective generation/approval reject. A filed claim alone does not stop minting.
Advertised malformed or unavailable Platform reads never fall back to Artist
approval. Existing Artist providers without the additive capability keep their
original economics path.

After the true author's corrective binding is accepted, the registry reports
its Artist consent mode. The original exact binding-associated operation-15
approval then applies, including the snapshot election/source wrapper. A saved
declaration or a prior live royalty consent cannot substitute for that approval.
The declaration and sustained history remain immutable. A declaration commits
to its statement hash; this read does not claim to load or independently mirror
narrative bytes or establish the statement's truth.

The original configured-key precedence is retained: collection overrides win,
including configured-disabled zero, and an actually missing collection may
inherit the configured default. Canonical source scope/hash, mode hash, token
hash, frozen token config, operation proof and event encodings are unchanged.
No default freeze or descendant freeze authority is added. The original four
prepared hooks, proof-before-no-op discipline, full source rechecks and atomic
rollback remain. Historical royalty disclosure stays storage-only through
later contests, corrections or unavailable Artist reads.

Focused tests include actual Core/Manager/Ledger/Resolver snapshots, complete
Safe rollback and identical retry, post-delivery contest rollback, malformed
authority facts and historical reads. The active-proof no-op case explicitly
impersonates the selected Manager to retain the actual pending Core/Ledger
window; it makes no additional Manager transcript claim. The Artist half reuses the actual original declaration/contest/correction
and Safe operation-15 recipes, with its existing typed unit Core boundary.
These complementary cases do not claim a new joined deployment, native runtime
result or transaction-capacity acceptance.
