# Typed WORK descriptions in LIDO

`tools.museum.work_lido` maps the complete supported
`STREAM_WORK_DESCRIPTION_V1` JSON interpretation into the original, pinned LIDO
1.1 schema. It accepts exact canonical source bytes and the complete catalog
witness when the WORK selects a catalog entry. The mapping profile is
`STREAM_LIDO_PROFILE_V1`; its generated bytes are prospective registration
inputs. This increment uses public fixtures. It does not establish record
publication, current selection, creator authority, catalog registration or
institutional acceptance.

Use the existing isolated Museum environment described in
[the tooling guide](../tools/museum/README.md). No additional dependencies are
required:

```text
python -m tools.museum.work_lido_fixture --check
python -m unittest tools.museum.test_work_lido_source tools.museum.test_work_lido -v
python -m tools.metadata.work_profile --check
```

`project_work_lido_fixture` accepts WORK bytes, context bytes, the expected
subject, context hash, exact mapping profile bytes/hash, the pinned LIDO schema
validator, and optional complete catalog bytes. It returns XML (or explicit
`None`), exact source sidecars, coverage, provenance and a report.
`verify_work_lido_fixture` reconstructs and compares every returned component.
The generator's check mode also requires the exact example file inventory.

## Required context and authority

LIDO requires an object type, work appellation, document language and record
source. An ARTIST identifier also does not supply the required creator display
name. The closed `STREAM_WORK_LIDO_FIXTURE_CONTEXT_V1` document provides explicit
supplemental statements. Its complete original bytes are retained, bound to the
WORK subject and payload hash, and checked against an externally supplied hash.
Each statement declares its author separately. One statement of each kind is
allowed; duplicate, conflicting, unknown and inactive fields reject.

| Statement | Meaning |
| --- | --- |
| `documentLanguage` | Explicit export language for primary WORK text without its own tag; `und` must be supplied, never defaulted. |
| `objectWorkType` | Explicit object-kind term and its language. Neither digital format nor absence determines this value. |
| `artistName` | Display name and language joined to all three original artist/association fields. Required only for ARTIST; rejected for NAMED or absence. |
| `workLabel` | Independently declared label naming the work itself, with `target=work`; accepted only for absence. A record/file label cannot substitute. |
| `exportPublisher` | Explicit publisher identifier, name and language used for the LIDO record source. It is separate from the WORK's declared author and creator. |

The source declaration ID, work ID and output-record ID must differ. Declared
author/publisher IDs cannot alias those objects. Identifiers do not create
Person/Group classifications or prove account control. A context author claim
does not prove authorship; the source declaration's claimed author applies to
WORK, not to the separately retained catalog. No fictional chain selector,
signature or registration is manufactured. The authenticated WORK source adapter
and current-selection join remain separate work.

## Fields and exact values

| WORK meaning | LIDO mapping |
| --- | --- |
| Title and ordered alternate titles | Separate typed `titleSet` groups; each language variant stays with its exact target. |
| Named or ARTIST creator | One creation actor, original name or separately attributed association-bound display name, and original claimed authority identifiers. |
| Exact creation date or inclusive range | Exact display value plus unchanged earliest/latest lexical dates; a single date uses the same exact endpoint twice. |
| Medium and AAT medium/technique references | Original display text and separately typed claimed concept identifiers. |
| PRONOM or selected catalog format | Explicit technical-description notes with exact PUID or specification URI/digest. Catalog IDs, algorithm and canonicalization evidence remain in the sidecar. |
| Pixel width/height | Decimal strings indexed with the explicit pixel unit, through the full supported uint256 range. |
| Aspect ratio and duration | LIDO display fields with exact numerator/denominator, including unreduced pairs. The original XSD recommends display for fractions; no decimal approximation is inserted into indexed measurements. |
| Unique, serial or open edition | Explicit unique literal, exact `number / total`, or unchanged authored open-series statement. |
| Credit line | Exact credit and variants, without inferring a rights license. |
| Inscription | A description, never a transcription or cryptographic signature claim. |
| Language variants and authority entries | Every original array position remains observable, including repeated values; no sorting, normalization or deduplication. |

The profile's generated controlled labels use `en`. Supplied context text and
WORK language variants retain their own tags and case. Document language does
not override those tags or imply a work's or creator's natural language.
Dates, text, authority identifiers and format references are source claims;
lexical validation does not establish external truth. A format-specification
URI is not a media resource. No resource record, MIME identification, retrieval,
fixity event, license, custody or creation-time authority is inferred.

The supported JSON interpretation permits Unicode characters that XML 1.0
cannot represent. Mapping rejects such text explicitly rather than replacing
or stripping it. Valid carriage returns, line feeds, entity-like strings,
quotes, astral Unicode and combining characters round-trip exactly through
serialization and reparse. The original complete WORK fixture containing
U+0001 is unchanged; the new XML example is separately authored.

## Explicit absence

`description_absent` remains an authored absence with its original reason and
date. With a separately declared work label, object type, document language and
export publisher, the mapper emits `catalogue-work-label` and two absence
notes. It does not add a creator, creation event, medium, edition or credit.
The original XSD's title documentation permits attributed descriptive or
repository titles; the supplemental label must still name the work itself.

If any required independent context is missing for absence, the result is
`accounted_absence_no_xml`, with no XML and no invented title. All original
WORK/context bytes and fields remain available. Missing context for a full
description is an error; it cannot silently turn a full description into an
absence.

## Validation and source accounting

The whole WORK and every catalog entry pass the accepted semantic validator
before projection. Applicable schema branches determine the inventory. Every
actual object, array position and primitive is recorded, together with absent
applicable optional fields, original schema locations and exact canonical
bytes. Inactive variants are not counted. Each row receives a mapped or
retained disposition. Unselected catalog entries, predecessor/profile/subject
references, association data, variant targeting and context controls remain
explicit evidence even where no faithful indexed XML field exists.

Provenance binds each emitted source value to its original document hash and
pointer, declared author where supplied, explicit transformation rule, final
XPath and exact target value. Paths are computed only after all siblings exist
and checked again against the serialized/reparsed XML. This preserves repeated
titles, actor identifiers and translated values. The report binds XML,
sidecar, coverage and provenance hashes.

The mapper reuses the existing `PinnedLIDO` object's unchanged original XSD
closure solely for schema validation. The earlier synthetic-assertion mapping
profile does not define these new WORK inputs. All 36 original documents,
their ordered include/import references and cycles remain pinned offline. The
two original XML namespace import warnings are retained. No upstream bytes or
earlier Museum examples are changed.

WORK/catalog inputs retain their separate 8,192-byte limits; context is at most
32,768 bytes. Each output is at most 4 MiB. XML uses the original validator's
depth-64 and 32,768-element bounds. These are deterministic supported-profile
limits, not a narrowing of the remaining full Museum scope. Broader authenticated
source joins, registered profiles, media/cross-format correspondence and
institutional ingest still require their own evidence.
