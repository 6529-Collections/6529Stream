# Authenticated conservation selection profile

`StreamConservationRecordSelection` interprets actual collection metadata records
under the complete supported conservation JSON profiles. Its explicit selected
histories distinguish original artist intent from later estate statements. The
pure serializers establish exact meaning; this layer additionally authenticates
original recorded authority, association and payload bytes. Finality aggregation,
archive delivery, factual truth and complete production deployment are separate.

## Fixed sources and complete interpretation

Construction pins the Core, Metadata host, Schema registry, Store and their runtime
hashes on the deployment chain. Metadata must already be Core-selected. Its pinned
artist facade resolves the actual Coordinator and Identity, Binding and
Attribution owners, including reciprocal chain/Core/facade links. These addresses
and code hashes are retained. No caller chooses an artist owner or alternative
source during interpretation.

Admission and current-use reads require that graph to remain current. They read
the Metadata-governed dependency cap, enforce parent-gas admission immediately
before bounded calls, require canonical ABI lengths and scalar widths, and reject
oversized return data. Compact document facts and ordered chunk reads reconstruct
the complete registered bytes of all eight conservation schema/profile documents
and the shared `RFC8785_JCS` definition. The exact immutable names, IDs, kinds,
canonicalization, hashes, lengths and applicable lineage are checked; documents
must be active for current consumption. Registration URI/name preimages are not
claimed to be reconstructed by the compact document header.

Full catalog witnesses reconstruct every original entry, including unselected
entries, and bind the selected entry to the complete registered catalog document.
Catalog IDs, whole hashes and lengths are retained in each selection. PRONOM
identifiers remain declared scheme-qualified identifiers; this does not identify
a retrieved file's format. The pure contract parser establishes BCP47 grammar;
the dated registry validation remains the offline profile tooling's separate
check. No case, language, source order, exact reference or Unicode value is
normalized.

## Original publication authority

Every supplied `CollectionRecord` is untrusted. The reader reconstructs its
original fourteen-word domain/chain/host/Core/recorder/collection/type/subject/
HashRef/URI/schema/signature/effective-time hash, resolves the actual nine-word
receipt, and checks the actual shared lane index and rolling chain. It reads the
whole original Store payload and compares it with the complete typed serializer.
The original receipt must use the exact schema and JCS definition hashes and the
artist branch of the actual Metadata policy.

The original consumed op24 authorization, saved publication object and host code
pin, attestation record, and complete stored versioned publication statement must
all agree. Intent and intent-waiver records use subject kind 7 and capability 64;
interviews use `ARTIST_STATEMENT`, subject kind 8 and capability 1. The original
authority class 1 authenticates an artist-origin statement. Class 3 authenticates
an explicitly estate-origin statement. The generic receipt's artist authorization
class 1 is distinct from these original artist-operation authority classes.

Each original must match the same current accepted or sanction-confirmed
artistId, generation and bindingHash, plus the immutable identity registration
hash. Ordinary key rotation or succession never rewrites its original author,
class, time or statement. Consumed signatures are not replayed, and present-day
signer capabilities are not reapplied to old obligations. Claimed artist fields,
participant identities and estate labels alone confer no authority.

## Explicit selected histories and locks

`adoptIntent` and `adoptWaiver` are permissionless delivery of an authenticated
statement's exact predecessor rule. They require the exact expected selected head
and revision. Each artist/estate lineage has its own history. Within that lineage,
each original intent or waiver lane advances monotonically by original index;
the signed predecessor orders transitions between those two separate lanes.
Publication time cannot decrease. Neither per-author latest nor an unrelated
generic append selects a head or vetoes an otherwise valid earlier candidate.

Unlocked lifetime artist chains can be materialized after succession, including
several already-published predecessors. Indexing is not new authorship. Estate
records have a distinct lineage and cannot replace the original artist voice.

`lockArtistIntent` seals a nonempty exact artist-origin selected head once. It
requires the actual current active artist principal in the pinned Identity owner
and the same current association. The direct principal may be a threshold Safe.
This surface has no relayed lock-signature lane. A lock freezes this selector's
artist head; it neither freezes identity keys nor blocks later generic dossier or
estate records. Core configuration freeze is not an intent lock. This bounded
selector lock does not claim complete generic Metadata lock-class support.

## Exact interview references and preparation

Intent presence and intent waiver each require their own explicit interview
PRESENT/WAIVED union. Interview waiver remains an explicit statement, independent
from any intent waiver. An absent witness cannot substitute for a waiver.

PRESENT commits to an exact chain/Core/Metadata host/original record locator and
the fixed interview schema/profile. The resolved original interview must carry
the same association and subject. Its own publication author and class remain
separate: an estate parent can reference an artist interview without relabeling
it. There is no independently mutable selected interview head.

`prepareInterview` can validate the full original interview in a separate
transaction. It saves immutable complete association, receipt/publication
evidence and catalog pins, keyed by the actual original hash within the fixed
host. It publishes a preparation commitment and identifies the preparer only as
the submitter of that validation. It grants no authority and selects no head.
Repeating an existing preparation is rejected. Standalone preparation reconstructs
its five applicable interview/catalog/JCS definitions. Parent adoption and
current-use require the complete nine-document interpretation set.

`adoptIntentWithPreparedInterview` and `adoptWaiverWithPreparedInterview` select
the original parent using that exact signed locator. Their nested interview
witness must be canonical empty. They recheck the current graph, association,
active definitions and complete catalog bytes, plus all ordinary parent
publication, CAS, predecessor and lock conditions. Preparation does not reserve
a head or survive a failed current-eligibility check as permission to select.
The ordinary full-witness entrypoints remain available.

The complete external payload Reference is separately committed in the selected
result. Exact JCS references declaring Keccak-256 or SHA-256 are checked against
the authenticated original interview bytes. Other algorithms/canonicalizations
remain `UNVERIFIED_REFERENCE` attributed correspondence, despite successful
original-record resolution. All six supported HashRef shapes remain available.
No URI equality, retrieval, archival fixity or offchain delivery is inferred.
The complete references remain retrievable in the original parent payload;
transcript/capture external content remains attributed source material.

## Current use, history and deployment boundary

`requireCurrent` checks the exact selected head/revision and current fixed source,
definition, association and catalog eligibility. Raw current/history,
preparation and lock getters preserve saved evidence without contacting current
providers. Retired definitions, pointer changes or corrected associations do not
erase historical receipts.

The behavioral fixture uses actual Metadata, Schema and Store with explicitly
typed Core/Executor/artist-owner boundaries. The separate actual Artist fixture
uses real owners, op24 and threshold Safes while retaining its declared Core and
governance fixtures. Those proofs are distinct from a complete deployed current
Core/Executor/provider graph. Complete delegated/collaborator authorization,
steward evidence, source archive coverage, original-artist waiver qualification
in finality, ten-input aggregation and full Museum conformance remain separate
requirements. A successful selection alone establishes none of those gates.
