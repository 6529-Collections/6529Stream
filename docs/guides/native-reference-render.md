# Native reference-render publication

`StreamReferenceRenderPublication` publishes an original curatorial observation of
an actual native collection snapshot and the first and last retained mint serials.
It never changes the script, content root, Router, entropy, artist identity, or
rendering authority. This is the COLLECTION / ONCHAIN / still / BYTE_EXACT profile.
It requires both curator-declared STATIC artwork and one fixed registered STATIC
renderer declaration. Other scopes, DYNAMIC, PERCEPTUAL, CURATED and other capture
classes remain required profiles; a successful still does not establish them.

## Original authority and retained meaning

The new observed-reference type is explicitly allocated to the existing CURATOR
family. An actual Metadata collection class-3 grant takes precedence over global
scope-0 class-8. Both grant revision and original recorder are retained. Snapshot
class-7/8 authority does not authorize this record. Revoking a grant prevents new
publication without rewriting an admitted original. Curator classification is an
attributed assertion, not artist authorship, proof of arbitrary JavaScript being
static, or satisfaction of a renderer registration static-analysis/golden gate.

The constructor binds Core, Metadata, Schema, Store, Router, Snapshots and the
external-object coverage host by address and runtime hash. It also binds exactly
one renderer catalog ID, hash and full byte length. Deployment only checks the
fixed early getters and original Metadata Executor runtime pin; it does not read
current sources, a Coordinator, discovery, Finality or a future Registry. A caller
cannot choose a different STATIC catalog for a renderer already declared DYNAMIC.
Complete active original schema/profile/catalog bytes are reconstructed from the
actual registry and immutable Store at publication and current consumption.

The original manifest retains all package and platform-prerequisite rows, both
full sample HTML documents, original coverage tuples, source pins, actual original
coordinators and finalized seed values, the snapshot binding, and original
publication attribution. The renderer declaration pins the actual renderer
runtime, Router module version/manifest, context, presentation and dependency
read-set. Full original first/last checkpoint leaves are joined to Core identity
and historical Router JSON. Retained burned endpoints remain applicable; live
supply and ownerOf do not select the sample. Unresolved entropy cannot become a
zero default. A genuinely finalized zero seed is retained as such.

Package and platform file arrays are prepared separately through permissionless
`prepareFileInventory` calls. Each preparation validates and renders the entire
ordered array, retains its exact JSON in the actual Store, and uses a key committing
domain, chain, host, relative/absolute interpretation and every complete ABI row.
It creates no reference head, writer grant, archive receipt or publication clock.
An identical prepared key is immutable and can be reused only after its bytes pass
integrity checks. Final publication requires the exact keys of both supplied arrays
and checks all ordinary current source, archive and curator predicates atomically.
The final complete JSON is unchanged; no file is omitted to save transaction gas.

Whole canonical manifest bytes and the complete canonical ABI Publication are
retained through actual Store chunks. Every read checks exact length, STOP prefix,
per-chunk digest and full digest. Uploading chunks gives no writer authority.
The JSON payload and the original ABI witness must each fit the Store reader's
524,288-byte bound; fitting the JSON bound alone does not admit a larger ABI witness.
`referenceRecord` returns exactly `abi.encode(Publication, Receipt)` at the ABI
boundary, using the linked decoder with explicit original storage references.
No storage overlay or caller-chosen storage root is used.

Linked source and outer-JSON calls receive explicit projections containing only
the original fields those functions read. The projections omit file-array copies
from those calls; the complete original arrays still determine the preparation
keys, full environment bytes, original record hash and retained ABI witness. The
prior complete outer serializer is retained as a test oracle for exact output
equality. These projections create no alternate source of authority or content.
The two publication entrypoints decode the complete input once into memory; their
internal readers do not mutate that original. This preserves the external ABI and
avoids repeated full-array decoding before the original record is retained.

The record hash commits its domain, chain, publisher host, Core, Metadata, complete
Publication and complete Receipt with `recordHash` and `recordChainHash` zero.
`recordedAt` is included in that outer record preimage. The JSON manifest excludes
these later receipt fields. The environment excludes its own hash/length, which
the outer manifest commits. Snapshot head/revision and publication predecessor
are original provenance; later head/freeze bits do not enter immutable content.
Publication requires exact expected head/revision and source hash, and unique
per-collection reference IDs. Appending neither mutates nor deletes prior records.

## Runtime package and offchain correspondence

The actual runnable engine and named capture toolchain are archived as a complete
external ZIP object. A small descriptor or package manifest cannot substitute for
its whole-object byte size, SHA-256, Keccak and native Arweave data root. Each PNG
is also a complete covered object. The original two-family evidence requires an
ENDOWED Arweave inclusion slot and a distinct institutional possession slot plus
passing independent full-retrieval fixity. The exact proof model is documented in
[external-object archive](external-object-archive.md): quorum anchoring and signed
full-object observations are explicit trust boundaries, not Ethereum recomputing
all external file bytes or verifying native network consensus.

`tools.preservation.reference_manifest` validates canonical declared manifest
consistency, the pinned original native snapshot and complete preserved leaf
manifest, every actual ZIP member and whole-object digest/native root, actual
Router JSON to HTML to both capture files, and recorded loaded-module inventories.
It does not infer a live writer grant from local files or authenticate that an
observation was made by an independent human. The existing packaged capture tool
runs two fresh browser processes, rejects its unsupported features and resource
requests, preserves source/capture bytes and loaded modules, and compares actual
PNG bytes. These guards do not prove arbitrary executable JavaScript dependency
closure or artwork classification.

The native environment is Windows/AMD64, a named exact OS version, software raster,
sRGB and DPR 1, with bounded explicit viewport dimensions. Package rows include
all executable/toolchain files; platform rows name external OS/loader/system DLL
requirements. No self-contained OS image claim is made. Onchain lexical checks
preserve ASCII relative paths and byte order; full Windows reserved-name and
case-alias checks belong to the offline package validator. ZIP member containment
and execution correspondence remain the curator's original attributed declaration
corroborated by the retained local checks, not onchain ZIP parsing or execution.

The preserved proprietary-browser license basis is `undetermined`, with its exact
original license note. This code increment authorizes no public binary upload or
redistribution. Redistribution licensing must be resolved before any such upload.

## Current consumption, locks and availability

Current consumption revalidates the actual graph, definitions, snapshot/source
facts and complete retained bytes. It uses the exact two original receipt hashes
for each object and compares every stable identity field. Later passing fixity
heads may restore current availability for those same receipts after the defined
failure/repair process. They cannot choose replacement receipts, another object,
family, locator, profile or artist. Saved original coverage is used in the source
hash, so routine PASS refresh does not change locked reference content. Current
coverage has no annual/quarterly scheduler or elapsed freshness gate; that broader
preservation cadence remains separate.

The host-local one-way reference lock requires the pinned actual Executor's exact
current class-2 action, scope, old and new transition hashes. It first validates
the selected current original. The lock cannot authorize other record families,
freeze generic Metadata, or supply artist content consent. Unlocked current reads
are distinct from locked current component readiness.

The host directly implements collection and scoped artwork finality component
interfaces, returning REFERENCE_RENDER only for the canonical collection scope.
Its component data hash commits original Receipt and Lock and excludes refreshed
passing fixity heads. Its constructor has no provider/Registry runtime cycle.

`StreamFinalityReferenceReads` pins Core, Metadata, Router, Snapshots and publisher.
It corroborates the publisher's exact canonical 20-word current receipt and
four-word lock, preserving original attribution, effective/recorded timestamps,
predecessor/revision and definition commitments. `requireCurrent` exposes unlocked
status; `requireLocked` requires the exact populated current lock. It relies on
the pinned publisher's original full variable-witness admission and current source
reconstruction; it does not independently rebuild that large original preimage.
A passing input is not aggregate finality, archive cadence, institutional acceptance
or complete runtime portability.

## Publication sequence

1. Register the exact schema/profile/format documents and the fixed renderer
   declaration. Deploy the publisher against its early immutable dependencies.
2. Obtain the current original Snapshot and complete retained mint inventory.
   Export the historical Router JSON for its first and last serials, preserving
   every byte of the native HTML and the original seed/token-data commitments.
3. Capture both samples with the archived toolchain, retain both repeated PNGs and
   execution reports, and verify the complete package and loaded dependencies.
   Unsupported features require another profile; a failed capture is not a waiver.
4. Admit the complete runtime and capture objects through the external-object
   receipt/proof/fixity flow. The onchain object identities must refer to those
   actual complete files, with the same artist and two independent original slots.
5. Upload each file inventory's canonical JSON chunks to the fixed Store and call
   `prepareFileInventory` for the complete package and platform arrays. Those calls
   may use separate transactions and do not reserve a publication or grant.
6. Call `previewReference` with the full Publication and intended curator. Set its
   exact expected source hash, retain the returned canonical JSON and the complete
   `abi.encode(Publication)` in the Store, then call `publishReference` as that
   authorized curator. A changed head, source or archive state causes atomic failure.
7. Read the original receipt/payload and verify current state separately. The exact
   staged terminal transition may lock the current record; only the locked current
   publication supplies the direct finality component.

The offline command is `python -m tools.preservation.reference_manifest`. Its
required inputs are the original manifest and an independently retained expected
Keccak anchor, `--snapshot-manifest` containing the original native snapshot JSON,
`--leaf-manifest` containing the complete canonical binary
[content leaf manifest](../integrations/content-leaf-manifests.md), complete runtime
ZIP, the report's restored runtime root, and one `--metadata` /
`--capture-directory` pair per required sample. The Python API likewise requires
`validate(raw, snapshot_bytes=..., leaf_manifest_bytes=...)`; its caller must
independently anchor `raw`. It reads the archived tool's literal controls without
executing that source during validation. Its
output explicitly reports local byte consistency separately from live authority,
network inclusion and execution attestation.

The reference pins the snapshot bytes, which pin the leaf bytes, checkpoint
producer, plan, count, ordered leaf chain and content root. The offline verifier
recomputes both commitments from every leaf, rejects repeated, missing or reordered
leaves, and matches captures to the exact first and last token IDs and their
metadata, HTML and token-data hashes. A singleton has one capture. Token IDs and
collection serials may have gaps after incident abort; `mintedEver` is an inventory
count, not the last serial. Burned completed tokens remain in this historical
inventory and need no live owner lookup.

The six-word content leaf does not contain a collection serial or lifecycle flag.
Those facts remain committed statements from the independently anchored reference,
whose original publication checked Core identity. After authenticating endpoint
membership, the offline verifier checks positive, increasing declared serials; it
does not independently verify Core serials or whether an endpoint was burned.
Changing a capture's serial changes the original manifest anchor.

## Validation and explicit fixture boundaries

The actual composition uses the real Snapshot, Metadata, Schema/Store, Router,
original-coordinator inventory and native policy readers, leaf checkpoint/manifest,
RoleRegistry, external-object coverage/checkpoint proof and upstream threshold
Safe. Core, Executor, artist/seed authority, the older leaf archive boundary and
network/institution/fixity observations are explicitly named fixtures. Local
signed observations do not constitute public archival delivery.

The full original browser package and first/last actual Router exports are retained
in the immutable delivery evidence directory. The earlier 447-byte local HTML
sample is only tool smoke; reference publication tests use actual exported Router
bytes and newly authorized original reference records. The complete 253,440,410-byte
ZIP has 364 members (including PACKAGE.json), with 108 explicit platform
prerequisites. The two source HTML documents are 447 bytes each; their repeated
PNG objects are 198 and 199 bytes. The emitted canonical manifest is 83,420 bytes
and is independently joined to those complete archive and capture files.

The matching actual composition passes 19 IR tests, including two 256-run
properties, original record/retained ABI and prior serializer parity, malformed
input, rollback/retry, grant, archive, lock and Safe controls. Six serializer tests
pass in both compiler modes, including two 256-run properties per mode. The offline
validator passes 18 tests and the definition generator matches the registered bytes.
These are focused cohorts, not a complete repository or full-v1 conformance run.

Cached probes reuse the exact compiled actual sources without recompilation:

| Timed call | Ordinary test context | Foundry `--isolate` context |
| --- | ---: | ---: |
| Publication with an explicit 16,000,000-gas call bound | 13,529,647 | 15,878,615 |
| Complete fixed consumer, 18 named targets cooled | 5,850,221 | 6,152,221 |

The consumer returns exactly 576 bytes. Package preparation separately succeeds
at 12,337,566 timed gas in the final actual cohort. The earlier isolated Safe publication trace
records 16,047,696 at its outer proxy, 15,114,663 at its implementation and
14,997,230 at the publisher. Those nested figures are not additive. Its inner
publication calldata is 105,700 bytes; its separately calculated Paris intrinsic
cost is 902,368. That calculation is not added to the isolated trace charges.
The probes preserve their actual envelopes and named-account cooling; they do
not establish all-account cold execution, another batch/transaction context,
all permitted inventory sizes, or another network's current gas rules.

The final Safe envelope test uses the complete `execTransaction` calldata and
ordinary two-of-two ECDSA signatures. For its isolated run, the 106,276 bytes
contain 67,900 zero and 38,376 nonzero bytes. With empty access/authorization lists,
zero value and no contract creation, intrinsic gas is 906,616 and the calldata
floor is 2,235,040. The floor is a minimum total, not a second deduction from the
execution budget. These formulas follow [EIP-7623](https://eips.ethereum.org/EIPS/eip-7623).

The test forwards exactly 15,870,600 gas, the
[EIP-7825 limit](https://eips.ethereum.org/EIPS/eip-7825) of 16,777,216 minus that
intrinsic cost, to the actual Safe proxy. The CALL-inclusive execution measurement
is 15,163,821; the resulting envelope is 16,070,437, leaving 706,779 gas. It checks
low-level success, canonical Safe `true`, the nonce increment and the original
class-8 publication. A preceding insufficient-gas call leaves the nonce and
publication unchanged, and the identical signed request then succeeds. The
ordinary-context run is retained separately with its own exact encoded bytes;
its byte counts and gas charges are not substituted into the isolated calculation.

This is a Paris-compiled and Paris-executed entry-gas simulation under Foundry
`--isolate`, with sufficient wrapper gas to avoid EIP-150 truncation. The test
wrapper's decoder and entry overhead are outside the simulated transaction to
the Safe. It is not a raw transaction receipt, proof of another execution fork's
equivalence, or a capacity bound for every supported inventory. Both probes reuse
the matching compiled sources without recompilation. All standalone default and
IR production runtimes fit EIP-170; the evidence separately records the fixed
reader's six-byte IR scratch-allocation variation between compiler contexts.
