# Render-critical inventory and archival bundle coverage

This implementation materializes a finite inventory from the actual native
collection source graph. The inventory and its archival coverage are separate
evidence. A content-leaf coverage hash, source inventory hash, or reference
manifest hash cannot substitute for either result.

The supported profile is an artist-associated COLLECTION scope with the native
onchain renderer and the admitted STATIC/BYTE_EXACT reference-render publication. Dynamic,
perceptual, curated, other scope families, and arbitrary JavaScript dependency
closure remain separate implementation obligations. An attributed STATIC
declaration does not prove that arbitrary JavaScript has no runtime dependencies.

## Original inputs and deployment

`StreamRenderCriticalInventory` binds the selected original content root,
snapshot, reference render, intent or intent waiver, interview status, RIGHTS,
and WORK evidence. An explicit interview waiver commits its authenticated
parent declaration and produces no invented interview original. Estate material
does not replace the selected original artist lineage. Historical author and
original publication grants retain their existing producer meanings.
The native presentation and conservation selection must agree on the fixed
artist registry/runtime, artist ID, binding generation, binding hash, and
original identity record. A shared artist ID alone cannot join different
original associations. The original nominated key is not substituted for an
original record signer; rotation and delegated publication remain distinct.

The dependencies are constructor-only storage. They include Core, generic
Metadata, Schema, Store, Router, the three typed selectors, Snapshot, Reference,
both archival providers, and the original Artist facade/Coordinator/Identity/
Attribution/Archive/Content owner pins. Construction does not query later
selection or a future complete finality provider. Runtime checks authenticate
the completed fixed graph. There is no callback from inventory into the
complete provider's finality-input read.

The eight inputs exclude these two new evidence outputs, the later finality
manifest, and its later sanction/signature archives. Those later objects retain
their independent original admission and archival gates. Exclusion avoids a
circular hash preimage; it is not an archival exemption.

## Materialization and current consumption

`beginInventory(collectionId)` derives a plan from the complete current original
context. Permissionless stages append native source bytes, the original
reference environment, typed WORK and RIGHTS, typed intent/waiver and interview,
the original content-root authorization, all 31 fixed interpretation documents,
and every token in the retained minted-ever inventory. Burned tokens remain
members. Each stage checks the fixed source graph and the relevant original
record. Final sealing repeats the full current-context comparison.

Every segment has a host/chain/plan/index-bound key, a source witness commitment,
an exact count, and a backwards item chain. Each link includes its segment key,
index, count, complete typed item, and successor. A zero successor is permitted
exactly at the last index. Final consumption checks both the exact aggregate
count and ordered segment chain. Repeated bytes in distinct roles remain
distinct occurrences. A package member, the package itself, rendered HTML,
token metadata, and a content leaf are different objects.

Every interpretation document is reconstructed from the actual registered
ordered chunks at admission. Its complete nine-word facts are retained and
rechecked at seal/current use, including definitions not selected by the current
intent/waiver branch. `requireFullDefinitionBytes` is a stronger diagnostic that
also reconstructs every byte again. The ordinary current path relies on fixed
Registry/Store identity and ordinary EVM immutability of admitted STOP bytecode
for already authenticated bytes; it does not promise equivalence under arbitrary
test-state edits.

`requireCurrent(collectionId)` returns the 19-word inventory evidence, including
the exact eight originals, scope, source context, member inventory, counts,
complete segment chain, and independently derived `renderCriticalEvidenceHash`.
`inventoryEvidence(planId)` is a historical read and does not establish current
eligibility.

## Exact objects, references, and applicability

The typed walks preserve every supported original Reference and complete catalog,
including unselected catalog entries. Hash algorithm and canonicalization labels
remain part of identity even when two references describe the same bytes. The
first correspondence profile verifies Keccak-256 or SHA-256 for RAW_BYTES/JCS
where the selected backend exposes the exact corresponding object digest.
Unsupported nonempty methods fail explicitly. They cannot become absent or
inherit coverage of a descriptor. The six-algorithm serializer vocabulary remains
unchanged; additional actual correspondence methods remain required work.

Native source objects include actual script/display/configuration bytes,
renderer/Router/Core runtimes, the full snapshot, original content-root and leaf
manifest, the complete leaf-list artifact, every retained original Coordinator
runtime/policy, and each member's exact token data, metadata JSON, image
applicability, and animation HTML. Current native policy inventory is not an
oracle-output or arbitrary execution-closure proof.

The reference inventory retains the whole executable archive identity, every
ordered package-file identity, capture objects, complete environment declaration,
and named OS prerequisites. Whole-ZIP coverage remains independent from the
per-file coverage. Per-file digest correspondence does not itself prove ZIP
containment; membership is the original attributed manifest plus the separately
verified whole-ZIP inventory. The native Windows prerequisite branch is explicitly
unarchived OS applicability, not a self-contained archived operating system.

`EMPTY_PACKAGE_MEMBER` retains an original package path, member index, zero size,
and the exact SHA256 of empty bytes. The authenticated reference declaration
must contain that exact empty identity. It is intrinsically reconstructible;
no nonempty native object, storage receipt, or dual-family coverage is invented.
The actual 364-member package contains three such files and 361 nonempty files.
The offline `tools/preservation/inventory_package_objects.py` joins every ordered
uncompressed member to the externally anchored complete ZIP, reconstructs each
nonempty member's flat digests and native root/proofs, and retains empty members.
These local checks do not establish public network delivery or signer authority.

`EMPTY_BYTES` means the reader derived an exact empty authoritative field. It
binds RAW_BYTES/Keccak(empty)/length zero and is intrinsically reconstructible;
it is not dual-family coverage. `ABSENT` records an actual supported applicability
decision, such as no token image or an explicitly waived interview original. A
caller cannot select either branch for a nonempty authoritative value.

## Original signed bundles

The CMC-ATTESTATIONS state-retention branch is explicit `STATE_BUNDLE`. Op24
retention binds the complete original ArchiveV2 envelope, original publication,
the original attestation record preimage and signer/class/time, and exact generic
Metadata receipt. The external Coordinator actor is an untrusted archive locator,
not a substitute signer. Op17 separately binds the original Content owner record,
Router content-root record, exact consent statement and original observed time.
The signed deadline is not substituted for the observed record time. Historical
proof is not reauthorized against today's signer, nonce, grant, or ERC1271 owners.

Exact original archival receipts and fixities retain their full state-readable
terms, locators, signatures, checkpoint certificates/proofs, and envelope bytes.
The onchain artifact's additive `originalArtifactChunkCoverage(completion,index)`
returns its immutable original per-part evidence. Passing refresh never changes
that locator. This finite original bundle does not recursively demand another
archive of the new coverage proof itself.

## Archival admission and refresh

`StreamBundleArchiveCoverage` consumes the exact completed inventory plan. Each
`coverNext` call authenticates the next complete item and its suffix against the
saved segment chain, then verifies the applicable actual archive proof. External
objects require the same original two receipts, independent families, passing
fixity and full tuple correspondence. Onchain objects require actual whole-byte
artifact coverage, every ordered STOP child, exact original per-part coverage,
and the retained original signed bundles. A descriptor's coverage never proves
coverage of the described executable or another payload.

The separately named immutable-STOP aggregate profile records each admission
under a complete current environment. It seals the ordered evidence chain and
count. Current use rechecks the complete mutable environment and cache revision.
The external host's health revision advances atomically for every successful
family admission/status write and every latest-fixity write, including PASS to
PASS. Its environment includes the actual current graph/configuration/profile/
chain pins. Current-role revocation is not silently added to old receipt
semantics; no annual/quarterly cadence or timestamp expiry is invented.

An environment change during initial admission or refresh cannot certify a mix
of epochs. A permissionless ordered refresh must cover every saved item under
one unchanged environment. Later passing fixity can update current observation
evidence for the same original receipts while preserving the immutable bundle
commitment. Failed fixity, family health changes, changed graph/runtime, or an
incomplete refresh prevents current success.

`requireCoverage(planId, expectedRenderCriticalEvidenceHash)` returns five words:
the inventory plan, its render-critical commitment, exact item count, immutable
evidence chain, and independent `bundleCoverageHash`. It does not repeat source
currentness. The complete provider must call inventory current once and join this
exact corresponding plan/hash. `bundleEvidence` is historical.
`requireFullCurrentCoverage` is the full per-item diagnostic: external items reread
the same original pair/current fixity, and onchain items reread STOP parts and
original bundle bytes. These methods do not claim arbitrary etched-storage
equivalence.

## Validation boundary

The matching IR cohort passes all 31 named tests, including five 256-run
properties, the complete 547-role bundle through both archival backends, full
refresh, actual Safe calls, original-author preservation, and exact parity with
the earlier 479-item reference/event construction. Separate focused allocator
oracles pass in both compiler modes, including shared dynamic aliases, later
allocations, every default field, and the original ordered item encoding.
Earlier external-environment, native/original-bundle, and package-tool cohorts
retain their own frozen source and runtime identities.

For this fixture, current inventory uses 10,130,862 gas after cooling 25 named
targets, within its 16-million callee bound. The complete bundle's cached current
read uses 149,064 gas after cooling nine named targets, within its 3-million
callee bound. These are specified current reads, not whole-account cold or
complete provider transaction measurements. The full per-item diagnostic remains
separate from the cached consumption path.

The reference stage's isolated Safe envelope uses 612 bytes of canonical
`execTransaction` calldata and two ordinary ECDSA signatures. Independently
recomputed intrinsic gas is 25,800 and the calldata floor is 33,000. The measured
Safe execution, including the inner CALL overhead, is 15,097,963 gas; the total
envelope is 15,123,763, leaving 1,653,453 below 16,777,216. The test forwards only
the remaining entry budget and requires canonical Safe success, one nonce
increment, all 479 roles, and the unchanged original curator. This is a
Paris-compiled execution-entry simulation, not a raw network transaction receipt
or modern-fork equivalence proof. Its wrapper overhead is outside the simulated
direct-to-Safe transaction. Other publication stages and the complete provider
must retain their own transaction-envelope measurements.

This is a working supported-profile increment, not release or testnet readiness.
It does not establish arbitrary maximum-size capacity or complete current-stack
assembly. The fixture's Core/Artist/Executor/seed/network boundaries remain
explicit; real source, record, archive and Safe operations within those boundaries
do not turn them into independently authenticated deployed authorities. Exact
whole-object digests and locally signed archival observations do not imply a
public archival upload, independent human fixity observation, or a licensing
decision.
