# Current-authority STATIC Artist source

This is an additive live attribution profile for an explicitly catalogued Artist
succession. It leaves the original immutable-A companion and existing preservation
profiles unchanged. It does not make an old Renderer admission cover new targets.

## Complete current authority

`StreamStaticArtistLineageSource(core, router, coordinators)` captures one to eight
complete actual suites. The first is the original Artist suite. Constructor reads
check the original Coordinator configuration hash, sixteen target runtimes,
finality/provider pins and seven Owner reciprocal bindings. All suites must retain
the same non-Artist dependencies. The source has no configuration writer.

The active Core pointer must select a catalogued, runtime-pinned Artist suite and
the same active Metadata Router. For a successor the source checks the one exact
immediate predecessor import binding, its root/manifest/snapshot and retained
runtime, the predecessor's seal to the selected target, and all seven matching
nonzero original hydration completion markers. A repeated successor must also
retain original A's exact immutable origin in the current Identity namespace,
with the matching completion, profile, owner index and nonzero imported revision.
An unlisted successor refuses; there is no pointer-following fallback.

The new `staticArtistLineage(bytes32)` Identity getter returns fifteen canonical
words from the original history/import namespaces. A zero query requests history;
a nonzero query also returns the original imported-origin facts. These are facts,
not a new authority certificate or mutation path. The fixed source validates every
required field. The existing Owner completion getter reads its identical original
storage word directly, avoiding a delegated library call during STATIC rendering.
All original authority, replay, import, checkpoint and economic writers remain.

## Rendering and admission

`StreamStaticArtistLineageCompanion(originalCompanion, lineageSource, executor)`
pins the original coordinates, catalogue source and two fixed workers. Its public
`attribution(collection, token)` derives the current suite itself, then executes
the original complete display algorithm through direct STATIC owner reads. Names,
claims, corrections, attestations, adverse state and sanction/confirmation display
remain current. The algorithm retains its final complete binding/state equality
checks. Calls transport the original read and membership caps explicitly to the
workers; the workers do not read an uninitialized gas-parameter namespace.

The live profile is `6529STREAM_STATIC_CURRENT_ARTIST_ATTRIBUTION_V1`. The separate
`preservationAttribution` projection has profile
`6529STREAM_CURRENT_ARTIST_NON_SANCTION_ATTRIBUTION_V1` and omits only the original
final sanction projection, including its existing state-three normalization. The
fixed worker's caller-supplied projection API is not a current-authority capability;
consumers use the companion's authenticated public API.

The selected Renderer must have a fresh governed declaration, complete read roster,
runtime pins, analysis and golden evidence covering every supported suite and fixed
worker. Catalogue membership alone is not admission. The Registry's existing target
and read limits still apply; the source's maximum catalogue length does not promise
that every possible catalogue fits a complete admitted roster. The new preservation
Renderer and its explicit admission-profile extension are a separate follow-up; this
batch does not permit old preservation consumers to reinterpret the new profile.

An original C2PA wrapper can point to the new live companion while retaining its
own reconciliation pins. Reports pinned to A can truthfully become `current=false`
after B/C selection. Current claims, standing and provenance changes may change
output. No output-equality promise suppresses legitimate current facts. Actual
C2PA serving and new preservation sibling integration remain to be exercised.

## Evidence and remaining work

The frozen source passes a 960-source ABI check. Native ABI/method-identifier and
recursive-layout comparisons retain 754 old ABI entries and 611 selectors across
ten affected products. All 280 old function bodies remain byte-exact except the
explicitly approved completion getter's identical internal-SLOAD call. The new
read creates no storage layout or namespace.

Fourteen authored tests compare original/full attribution bytes, original typed
namespace completion through A/B/C, current adverse facts, sanction-only projection,
unknown successor, all five imported-origin predicates, seventh-marker mismatch,
missing prefix, seal/snapshot/binding, runtime/chain/pointer and missing snapshot
refusal, plus fuzzed claims. They use actual new source/companion and original
Owner/Guards/import storage, with explicit typed Coordinator/history/fact/Core/
finality boundaries. They do not establish actual Identity deployment, Safe op60,
full Renderer admission, C2PA integration or cold transaction acceptance.

Selected product sizes and constructor data must be checked on the exact integrated
source. Earlier overflowing candidates remain diagnostic evidence, not acceptance.
Focused runtime and the actual Prepared A-to-B-to-C recipe are separate evidence.
