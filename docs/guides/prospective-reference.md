# Prospective collection reference

`StreamProspectiveReferencePublication` supplies the permanent conservation Floor's
pre-sale script-reference getter. It records one or two named simulation vectors
over the complete current native script and media descriptor. Each vector has an
explicit seed and opaque input bytes. It has no token ID, serial, original
Coordinator, finalized entropy, token snapshot, or finality-component capability.

The separate prospective HTML convention exposes `STREAM_PROSPECTIVE` with the
profile, original chain/Core/collection, source hash, vector name/hash, seed, and
Base64 input. Artwork code for this profile must use those simulation inputs.
The fixed encoder is separately pinned; an original renderer/version declaration
is source provenance, not a claim that this document is an actual token render.

This is the COLLECTION / native stable-or-chunked script / curator-declared STATIC /
still / BYTE_EXACT profile, using the existing finite Windows/AMD64 software canvas
capture environment. Names use 1–64 ASCII letters, digits, underscores or hyphens;
each input is at most 4,096 bytes, script at most 24,576, HTML at most 40,960. Library
dependencies, opaque/alternate media denominators, DYNAMIC work and other capture
or acceptance classes require their separate producers. VIEW remains separate.

## Deployment and authority

Deploy the permanent Core-bound Floor, then this reference host and its fixed
workers, then the conservation provider which pins this host. Admit that actual
provider through the Floor's original governed source transition. The reference
host constructor pins Core/Floor/Schema/Store/archive/encoder. It derives the
provider, runtime and configuration from the Floor's latest original source row
at publication and consumption, avoiding a mutual future-codehash deployment cycle.

The original selected Metadata CURATOR collection class 3 precedes global scope-0
class 8. The recorder, class and grant revision are immutable receipt fields.
Upload/preparation is permissionless and creates no publication authority. Source,
head and writer are checked again before the authorized state transition finishes;
late failure rolls back both retained manifests and record/index/replay writes.

Register all three new exact generated documents and the unchanged environment,
PNG/ZIP, format and renderer declaration definitions. The constructor fixes one
active STATIC renderer catalog ID/hash/length. Generate or check the additive docs:

```powershell
python -m tools.preservation.prospective_reference_profile
python -m tools.preservation.prospective_reference_profile --check
```

The new schema is `STREAM_PROSPECTIVE_REFERENCE_ABI_V1`; profile is
`STREAM_PROSPECTIVE_NAMED_SIMULATION_PROFILE_V1`; canonicalization is
`STREAM_ABI_PROSPECTIVE_REFERENCE_V1`. The schema includes complete standard ABI
tuple components and all enum mappings. Existing registered V1 bytes are unchanged.

## Capture and publication

1. Read `currentSource(collectionId)` at the intended pinned chain/block and retain
   that original export. Read `simulationHTML(collectionId, vector)` for each named
   vector. Confirm the tool's independently encoded HTML equals those exact bytes.
   Do not replace source authentication with a JSON file merely carrying a hash.
2. Use a source export with exactly `chainId`, `core`, `collectionId`, `sourceHash`,
   `vector: {name, seed, input}` and `scriptHex`. Integers are JSON integers and hex
   is lowercase `0x` form. Execute the same archived engine in two fresh processes:

   ```powershell
   python -m tools.preservation.prospective_capture capture --engine <pinned-chrome.exe> --context <source.json> --output <fresh-run> --width 512 --height 512
   ```

   The original native canvas restrictions, network/resource denial, JS-error
   refusal, software raster checks, sandbox check and full native module inventory
   remain. The new tool accepts only the separate prospective HTML wrapper. No
   browser was launched merely by building or type-checking this feature.
3. Retain the entire runnable engine/Python/toolchain/dependency tree, exact
   platform prerequisites, actual HTML and complete script/media bytes. The ZIP's
   complete ordered file inventory must include `prospective/script.js`,
   `prospective/media.abi` (the full canonical typed media descriptor), and
   `prospective/<vectorName>.html`. Include this tool, original imported capture
   module, Python/stdlib, websockets, Crypto and their actual native dependencies;
   test restoration and execution without host-path fallbacks. The existing
   package-tree inventory/restore helpers may transport a complete supplied tree;
   their inventory alone does not establish executable dependency completeness.
4. Obtain actual full ZIP and PNG object identities, native archive/fixity evidence
   and current two-receipt coverage through the original archive producers. Populate
   the full original Environment, generate its exact canonical JSON and hash/length.
   The same media's original master/waiver producer independently proves required
   display/master preservation; a media URI is not archive evidence.
5. Produce the exact nine-word execution observation after the environment is known:

   ```powershell
   python -m tools.preservation.prospective_capture execution --run <fresh-run> --environment-hash <exact-hash> --output <new-execution.abi>
   ```

   It binds profile/source/vector/environment/HTML/two-PNG hashes/time/status and
   checks retained original capture files. It is an attributed local observation,
   not an EVM execution proof or a signature. The execution ABI stays outside the
   ZIP to avoid a self-hash cycle. `effectiveAt` must not precede `capturedAt`.
6. Populate Publication, using `expectedSourceHash` from the actual source export,
   original head/revision, unique reference ID, reason and optional valid content
   URI. `previewProspectiveReference` derives the exact canonical payload; a zero
   source field is normalized only for preview. Upload every 8,192-byte chunk of
   that payload and `abi.encode(Publication)` to the original Store. Existing
   per-64-row file-inventory and environment preparation methods are available;
   their identities remain bound to this actual host and chain.
7. The granted curator calls `publishProspectiveReference`. The exact consumer is
   `requireProspectiveCollectionReference(cid, subject, semanticMembership)`,
   returning one evidence hash after full fresh source, definitions, original
   byte integrity and current archive coverage. Subject is the canonical COLLECTION
   subject, not a RELEASE label. Source drift makes this getter unavailable; original
   record/payload/history remain readable.

## Relationship to later evidence

A permanent Floor may retain an already-successful receipt for the same semantic
release under its own original rules. This does not rewrite a prospective source
record or make its current getter accept drift. Newly introduced semantic content
requires its own genuine current prospective record before its FULL first sale.
Later actual token identity/serial, terminal/finalized output, required first/last
captures, complete output inventory and finality ceremony are still required.
No pre-sale vector is promoted into those later denominators.

## Validation boundary

fuzz runs, using the actual new publisher/workers and Store with explicit typed
Core/Floor/provider/Metadata/Router/Schema/archive boundaries. The fixture is
deliberately zero-mint and uses synthetic capture and archive facts. The first
capture retained five passes and six failures because its fixture omitted the
original file-inventory preparation; the successor adds that preparation and a
positive simultaneous collection/global grant precedence assertion. Production,
compiler settings and all ten schema fixtures are unchanged.

22,809 runtime bytes and 26,785 creation bytes. The exact 120-source capture joins

current-stack governance/Safe/floor transaction, genuine browser replay, complete
package restoration or transaction-capacity acceptance. Whole-test gas includes
uploads and multiple calls. Existing metric publisher native16 seven-pass/two-
failure evidence is unchanged by this batch.
