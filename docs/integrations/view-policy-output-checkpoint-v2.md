# Adopted VIEW policy output checkpoint V2

`StreamViewPolicyContentCheckpointV2` observes the complete ordered token list of
one currently adopted VIEW V2 source. It is a permissionless output checkpoint,
not a new Artist consent book, metadata publication, browser execution, archival
coverage, snapshot, reference receipt or finality decision. Original Router op17
adoption and its one tagged history remain the authority for the selected view.

## Deployment and source identity

Deploy after the original Core/Router and the exact-source
`StreamViewCheckpointServingV2` adapter exist. The constructor takes the complete
`StreamViewPolicyCheckpointTypesV2.Configuration`: Core/Router/Router governance
authority/serving adapter addresses and runtimes, the adapter configuration hash,
chain id, read gas and serving gas. It pins its two fixed linked source/token
workers too. No per-scope source set, renderer or future finality provider must
exist merely to construct this checkpoint. It is a supplemental product, not a
replacement or renumbering of a canonical genesis role.

Each operation starts at the actual pinned Router's full VIEW scope head. The
source worker authenticates its saved V2 tag, immutable carrier, canonical record
and source preimages, then derives the original dependency roster from that
record. The unchanged full current-source reader independently joins today's
selected Artist/Finality/provider/Metadata, complete declaration and Store bytes,
ACTIVE schemas, admitted renderer/version/read set, actual factory/source-set
plan and full policy roster, and authentic membership. Caller-supplied addresses,
source hashes and projections are not accepted by the host.

The scope is `(VIEW, collectionId, 0, scopeId)`. Its sealed membership identity is
distinct from the declaration's `viewId`. COLLECTION, TOKEN, RELEASE, SEASON,
zero members and incomplete policy sources are not interpreted as this profile.
The existing finalized-only VIEW V1 source remains a separate profile.

## Prepare and validate the complete output

1. `begin(scope, salt)` derives a plan from the complete current source. Its id
   binds chain, this checkpoint, configuration, all four scope coordinates,
   source context and actual token count. An identical existing plan is retained.
2. `append(id, expectedTokenId, json, html)` observes exactly the next original
   membership ordinal. It checks permanent Core identity, actual collection
   serial/lifecycle, original coordinator at mint and the exact full-policy or
   legacy rule. The same authentic adapter renders modes 2 and 3; supplied bytes
   must equal both complete outputs. One row becomes preparation only after all
   reads and comparisons succeed. Duplicate, skipped or out-of-order tokens
   cannot stand for the complete list.
3. `seal(id)` requires all rows, reruns complete current-source authentication and
   observes every row again, including both outputs. Only exact equality derives
   a nonzero output root. No persistent cached currentness is used.
4. `requireCurrentCheckpoint(id)` requires a sealed checkpoint and repeats the
   same complete validation. `checkpoint` and `outputAt` are retained historical
   reads and do not assert current eligibility.

Every row binds index, actual token id and serial, lifecycle, burn flag and serving
kind, exact tokenData hash, coordinator/runtime and complete entropy facts, and
JSON/HTML hashes and lengths. The fresh full policy is never replaced by a status
number or invented seed. Terminal statuses 1/2 require the original terminal
policy and zero seed/request; finalized status 5 retains its actual seed and
finalized rule. Prepared or pending tokens refuse.

`servingKind=1` is the actual current live-token output. `servingKind=2` is a
genuinely completed-then-burned member observed through the retained adoption's
historical adapter path, with lifecycle 3 and `burned=true`. It does **not** assert
that a burned token has a current output. The adoption and complete source still
have to be current; a historical row cannot bypass current source-set membership
or eligibility. Live Artist annotations remain part of both actual output paths,
so drift can invalidate a saved checkpoint while its original rows remain readable.

## Exact new commitments

All structured commitments use Solidity `abi.encode`. The profile is
`keccak256("6529STREAM_ADOPTED_POLICY_VIEW_OUTPUT_CHECKPOINT_V2")`.
The source context uses `6529STREAM_ADOPTED_POLICY_VIEW_CHECKPOINT_SOURCE_V2`
and binds profile, chain, actual checkpoint, complete configuration, scope,
adoption record/source hash and full policy binding.

The plan uses `6529STREAM_ADOPTED_POLICY_VIEW_CHECKPOINT_PLAN_V2`. The initial
row chain uses `6529STREAM_ADOPTED_POLICY_VIEW_OUTPUT_CHAIN_V2`, plan id, full
scope, source context, membership hash and exact uint64 token count. Each row
hash uses `6529STREAM_ADOPTED_POLICY_VIEW_OUTPUT_ROW_V2`, chain, actual checkpoint,
plan id and the complete typed Output. The ordered chain adds each uint64 index
and row hash. The final root uses `6529STREAM_ADOPTED_POLICY_VIEW_OUTPUT_ROOT_V2`,
chain, actual checkpoint, configuration hash, plan id, scope, adoption record,
source context, token count and complete row chain. None reuse a COLLECTION or
V1 output root domain.

## Validation boundary

The authored twelve cases use the actual new host, original full current reader
and Documents, State/Store carriers, Renderer and exact-source adapter. Core,
Artist, Metadata, Schema, Registry, Membership and factory/source set replies are
explicit typed boundaries. They do not prove a real op17 signature, governed
renderer admission or the current complete deployment graph. The native2 capture
passed all twelve cases after correcting a stale fixture attribution Router reply.
The original native1 setup failure remains retained. All 107 source texts and 20
artifacts were authenticated; all 19 reached production products fit, and every
production bytecode remained identical across the fixture-only retry. The tests
ran without compilation or artifact mutation. These results do not establish a
complete governance ceremony or universal cold transaction capacity.

The original Router FULL_VIEW_GAS and transaction limits are unchanged. This
checkpoint supplies its own immutable serving budget to the pinned adapter. A
row performs both output reads and complete source authentication. Seal/current
cost grows with the complete member count and output sizes; incremental append
does not prove the final complete read fits an admitted transaction budget. No
whole-scope or cold-gas acceptance is claimed until measured.

A covered full output manifest, scoped snapshot/reference/inventory consumers,
actual repeated archived execution and combined provider/finality wiring remain
separate required continuation work. Hash-only observations cannot substitute for
those complete bytes or authority joins.
