# Scoped full-policy preservation and deployment

This additive TOKEN, RELEASE and SEASON path follows the
[scoped-policy snapshot and Router root](scoped-policy-publication-v2.md).
Every producer has a distinct V2 capability and profile. Original COLLECTION and
scoped V1 bytes retain their original interpretation.

## Publication and preservation order

1. Complete the authoritative membership and original coordinator inventory;
   prepare its genuine scoped-policy source set.
2. Prepare the seven publication contracts from the fixed recipe described below.
3. Complete selection, rendered content checkpoint and covered output manifest.
4. Publish the root-free snapshot, then adopt the actual Router root using
   original Artist CONTENT_ROOT operation-17 consent.
5. Publish the scoped-policy reference against that exact snapshot and root.
6. Complete the ordered render-critical inventory, then archive its exact items
   through the scoped-policy bundle producer.

Current admission remains separate from immutable historical records. A later
root or source change can stale a current reference or inventory without
rewriting an original record. Locking a publication remains an exact original
Governance action; deploying a child confers no publication authority.

## Reference observations

`StreamScopedPolicyReferencePublicationV2` retains the original CURATOR grant,
bounded environment preparation, canonical Store bytes and class-2 lock model.
The new source includes the full scoped-policy snapshot, actual common Router
head, exact 23-field V2 interpretation binding and ordered sample observations.
Every join checks the full scope tuple, including the collection of a TOKEN.

The BYTE_EXACT profile samples the first and last scope members, or the sole
member of a TOKEN. Samples retain the original at-mint coordinator, complete
policy readiness and separate terminal admission. Terminal DISABLED or ASYNC
NOT_REQUIRED output keeps zero seed and `finalized=false`. A sample does not
replace the complete membership or full rendered-byte archive.

The three new registered documents are
[schema](../schemas/preservation/scoped-policy-reference-v2.schema.json),
[profile](../schemas/preservation/scoped-policy-reference-v2.profile.json) and
[canonicalization](../schemas/preservation/scoped-policy-reference-v2.abi.json).
Metric producers and their original definitions remain separate.

## Complete inventory and archive bundle

`StreamScopedPolicyRenderCriticalInventoryV2` retains the original staged,
ordered inventory interface. The native source rows include the actual factory,
its exact dependencies, complete original policies, source runtime and root
binding. The remaining stages preserve reference files, registered definitions,
descriptions, conservation, interviews and every token's rendered sources.
Historical root authorization reconstructs the V2 record with its binding and
the aggregate recorded at publication, then verifies the original signed family
and operation-17 authority. A later aggregate is not an interchangeable input.

`StreamScopedPolicyBundleArchiveCoverageV2` admits that exact inventory under
distinct V2 domains. The original whole-byte coverage, Artist Archive receipts,
fixity checks and ordered environment refresh rules remain in force. Its
`requireCoverage` verifies the bundle's archival liveness. A finality consumer
must also call the matching inventory's `requireCurrent` and compare the exact
scope, plan and evidence hash.

## Fixed recipe factory

`StreamScopedPolicyPublicationFactoryV2` binds one immutable recipe at
construction. It pins Core, Metadata, Router, membership, selection, the actual
scoped entropy factory, executor, preservation hosts and every expected runtime.
Snapshot and reference slots in the supplied inventory recipe must be zero;
only this factory's genuine children fill them. Original late Artist and record
hosts have fixed nonzero addresses and runtime expectations, checked on use.

`prepareGraph(scope, maximumChildren)` creates up to seven children in order:

| Index | Child |
| --- | --- |
| 0 | Terminal entropy readiness |
| 1 | Scoped-policy content checkpoint |
| 2 | Scoped-policy output manifest |
| 3 | Scoped-policy snapshot |
| 4 | Scoped-policy reference |
| 5 | Scoped-policy render-critical inventory |
| 6 | Scoped-policy archive bundle |

The maximum must be between one and seven. Separate fixed deployment workers
create the children in the factory's context. Progress is append-only and
idempotent for the actual current entropy plan. A failed transaction rolls back
all children and progress created by that transaction; earlier stages remain.

`requireCurrentGraph(scope)` verifies the actual source factory's current plan,
source set, full policy route, selected Metadata and Router, all child runtimes
and exact constructor dependencies. It does not require a snapshot, root,
reference or inventory publication. This ordering avoids requiring a root before
its snapshot can be deployed. `graphForPlan` retains the original deployment
record independently of later current eligibility.

The factory has no setter for a recipe, host, runtime, source or implementation.
Snapshot and reference gas parameters may still increase through their original
governance mechanism. Those increases cannot change their source identities.
Consumers must pin the factory runtime, recipe and profile, and validate the
genuine current graph rather than accept an arbitrary supplied host.

## Validation boundary

Source/type checks and authored regressions cover publication joins, exact hash
preimages, ordered inventory stages, archive admission and factory rollback.
Fixtures identify their Core, Artist, late record and external archival
boundaries. Creating a genuine child graph does not establish complete finality
or actual production deployment feasibility. Native execution, full current-stack
acceptance, deployed size, transaction gas and matching release evidence remain
separate requirements. Provider/discovery integration is the next source batch.
