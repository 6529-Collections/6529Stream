# VIEW locator correspondence

This is a revision of two unreleased pre-genesis VIEW draft interpretations:
`6529STREAM_VIEW_PRESERVATION_RENDER_CRITICAL_V1` and
`6529STREAM_ARTIST_SANCTION_VIEW_MEDIA_V1` (transport profile 3). Neither was
present at the immutable RC `1569bf87`. The exact new sanction catalogue bytes
need fresh registration/admission. Existing registered documents cannot be
rewritten. Prior source-qualified captures remain retained and do not cover
this successor. Original generic Archive, profile 1/2, signing, subject, nonce
and raw-CID/absent row semantics remain unchanged.

A raw CID directly commits the file SHA-256. An exact institutional HTTPS URL
or canonical Arweave transaction identifier instead creates a locator
obligation with no content digest or size. The original external Archive pair
is the attributed correspondence evidence. The fixed VIEW-only reader requires:

1. The complete canonical source-qualified locator row and external backend 1.
2. The actual pinned Archive object's full bytes identity and nonzero size.
3. Original full object, coverage, signed receipts, fixities, native checkpoint
   and present pair liveness under the existing Archive reader.
4. Exact HTTPS bytes equal to the second/institutional receipt identifier, or
   exact decoded transaction bytes equal to the first/endowed identifier and
   its same checkpoint hash.

The institution's original signature and fixity observation establish an
attributed retrieval claim. The URL alone does not cryptographically imply the
digest. The transaction ID is not treated as a flat file digest either; original
native proof semantics remain separate from signed full-object fixity. No
current signer reauthorization replaces the original receipt. A matching
locator from a different object or pair is insufficient.

Cover, refresh, full-current coverage and finality media review all use the same
fixed reader. Every locator refresh re-runs complete admission and compares the
saved Admission. The original covered row stays algorithm 0, empty digest and
size 0; object materialization uses a deep copy. The bundle still binds both the
exact ordered row and its admitted original evidence.

The authored successor adds three pure grammar/row cases and nine Archive,
media/review and Bundle cases. They use actual original Archive, signed family
receipts/fixity/native fixture, actual schema catalogue and actual Bundle host.
VIEW declaration/current evidence boundaries remain typed. The large covered
fixture is an opaque browser ZIP; these tests make no image-decoder, real upload
or browser-execution claim. All cases are source/type-check evidence only until
an explicitly recorded native run. No shipping transaction or maximum-scope
capacity conclusion follows.

## General retrieval successor

The bounded source-qualified implementation described above remains retained. The
new [attributed retrieval satellite](view-attributed-retrieval-witness.md) and explicit
companion-enabled consumer profile implement the following requirement in a separate
source batch. Its runtime and transaction-capacity acceptance remain separate.

The bounded implementation deliberately cannot resolve an arbitrary origin URL
to a different preservation URL, nor an `ar://transaction/path` manifest route.
That successor uses an actual attributed producer with this retained
observation: exact requested URI, ordered redirects or manifest resolution,
final retrieval URI, observation time, complete content Keccak/SHA-256/size,
original Archive object and exact covered receipt pair, and the authenticated
VIEW adoption/full scope/source record. Its own signed preimage, writer authority,
nonce, expiry, revocation/currentness, canonical encoding and immutable full-byte
retention must be explicit. A URI owner or arbitrary caller-supplied boolean
cannot establish that evidence.

The producer receives the complete URI from the actual adopted source,
joins the full-byte retrieved object to the existing same-pair Archive proof,
and retains the redirect/manifest witness. A consumer must verify the fresh
writer authorization and observation domain plus current archive liveness,
without equating an observation with permanent HTTP content immutability.
Reference Environment currently has no such URI-resource table; an unrelated
package member or matching filename is not a substitute. Otherwise-valid media pass completeness only through that explicit successor
and its actual signed correspondence checks; the old bounded locator reader alone
still refuses them.
