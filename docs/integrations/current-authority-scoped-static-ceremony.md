# Current-authority scoped STATIC ceremony recipe

This is a source-authored integration recipe for TOKEN, RELEASE and SEASON.
ABI-only compilation and source review are distinct from native execution,
browser capture, complete archive admission and Finality acceptance. The three
[composed cases](../../test/current/StreamCurrentAuthorityStaticScopedPolicy.t.sol)
do not establish a completed ceremony. They retain strict production checks,
including integration dependencies identified below.

The recipe extends the [original deferred graph](current-authority-deferred-policy.md).
Metadata, Router, WORK, Conservation, Finality, Discovery, Artifact and archive
anchors remain original. Current Artist authority changes only through actual
complete A-to-B-to-C recovery and Core selection. Scope records never inherit
the independent collection-level WORK, Rights or Intent selections.

## Actual publication order

1. The [STATIC prefix](../../test/helpers/StreamCurrentAuthorityStaticPrefixFixture.sol)
   deploys and admits the renderer, its configuration and actual source/read
   roster before Artist onboarding, the first release ratification and minting.
   Its schema/analysis/golden inputs are explicitly synthetic fixture evidence;
   they do not prove renderer admission conformance. After token 1 receives its
   real finalized entropy, the helper admits the actual CurrentCitation before
   the first Core `tokenURI` read. Gas increases use ordinary governed calls;
   the chosen simulation budgets are not measured deployment parameters.
2. The [scope publisher](../../test/helpers/StreamCurrentAuthorityScopedPolicyPublicationFixture.sol)
   registers TOKEN identity or an actual RELEASE/SEASON membership record and
   local Metadata subject. It seals full membership and coordinator inventory,
   creates the actual entropy source set and all seven factory children, and
   publishes selection, full-output checkpoint, covered output manifest,
   snapshot and original Artist op17 CONTENT_ROOT. These original Router
   publications occur while A is current. STATIC has no native checkpoint/root;
   the native head remains zero and its exact empty-family hash participates in
   the signature. Every scoped root retains its own historical aggregate and
   original signed family, including when a later scope changes the aggregate.
3. The [record publisher](../../test/helpers/StreamCurrentAuthorityScopedRecordsFixture.sol)
   uses the original Metadata host with actual current B/C op24 authorization.
   It publishes WORK, a full Interview and full Artist Intent with a PRESENT
   Interview locator, then adopts the scope's exact selected heads. Metadata
   prepares large payload bytes before authorization. The recipe retains full
   receipts, original owner records, collection-wide record indexes, payloads,
   selection history and exact predecessor comparisons. Documentary references
   contain deterministic fixture statements, with no claim of real testimony.
4. The [Rights and sealing helper](../../test/helpers/StreamCurrentAuthorityScopedPolicySealingFixture.sol)
   separately publishes a real class-7 RIGHTS-family record. Its ACCOUNT
   licensor and unspecified grants make no legal ownership or permission claim.
   It exercises a rejected wrong-head selection, exact governed WORK/RIGHTS
   seals and the current recovered Safe's Intent seal. An ordinary publication
   caller cannot substitute for those lock authorities.

The three cases retain independent original collection records and seals,
publish B scope records and Rights, import C completely, append successor C
WORK/Interview/Intent, and seal the exact scope heads. They compare original
Metadata bytes/receipts, B selector history, original Router root records,
original presentation, fixed anchors and current routes throughout. They do
not manufacture a Reference or skip a required archive stage.

## Fresh observation and complete inventory

The [export helper](../../test/helpers/StreamCurrentAuthorityScopedPolicyExportFixture.sol)
accepts a task-owned fresh directory and run label. It re-reads actual current
scope membership and Router HTML/JSON, requires exact checkpoint hashes, and
exports the complete scope and original publication identities. Use these exact
HTML files with the [capture tool](../../tools/preservation/reference_capture.py)
and the explicitly selected engine/viewport. The helper itself does not run a
browser. The earlier native fixture's historical JSON and capture files are not
valid substitutes for this scoped full-output profile.

The [reference helper](../../test/helpers/StreamCurrentAuthorityScopedPolicyReferenceFixture.sol)
accepts complete supplied environment ABI, runtime ZIP proof inputs and fresh
first/last PNG observations. It checks actual Core serials, full current Router
HTML/JSON and accepted checkpoint rows. Both repeated PNG identities must match
the actual archived object. It retains file inventories, canonical environment,
publication, complete source facts and receipts, then optionally performs the
actual governed reference lock. Its archive observers remain fixture signers;
successful local publication would not establish live Arweave delivery.

The [inventory helper](../../test/helpers/StreamCurrentAuthorityScopedPolicyInventoryFixture.sol)
traverses all native, reference, record, root, definition, token and origin
stages using stored cursor/count evidence. It uses current captured authority
to locate each original op17/op24 receipt, including imported A/B occurrences.
It checks the actual version-2 segment events against stored commitments. A
wrong historical root aggregate must revert without advancing the plan; the
exact independent original witness is then retried. Counts are derived from the
actual scope and stages, never copied from the earlier native fixture.

Complete source inventory is separate from coverage of every byte occurrence.
The [bundle helper](../../test/helpers/StreamCurrentAuthorityScopedPolicyBundleFixture.sol)
requires complete retained source bytes and fresh per-member endpoint proofs.
It reconstructs every segment link and admits exact original bytes, complete
package membership and actual origin state bundles through child 6. It verifies
each saved item, proof and origin, then bounded and full coverage diagnostics.
Schema and canonicalization identifiers remain unchanged when proving byte
correspondence. No missing coverage, zero receipt, sample or skipped row can
stand for a completed bundle. A complete caller collecting these byte witnesses
and fresh browser inputs, and its actual execution, remain integration work.
The current in-memory proof API also retains all package endpoint buffers in
its parent frame. A large-package caller needs streaming proof preparation;
external self-calls alone do not release those retained parent buffers.

## Integration and validation boundaries

Review against integration source `478c0824dcff34d493577b22ce8a172df4ff9daf`
identified these concrete dependencies. They must be resolved and tested on the
combined source before reporting positive post-succession preservation:

The later integration must include the completed Metadata subject-registration
repair `0aee507bb0648a90ebc4e41059cc610a828d724c`, including its factored path and
self-read budget. The initial `478c0824` API alone is not the final tested repair.

- The original STATIC attribution companion pins A. Its Artist reader rejects
  Core's B/C pointer, changing current JSON to an unavailable attribution. The
  old full-output checkpoint correctly becomes stale.
- The original Rights selector's currentness path requires its constructor's
  A Artist pins, including for ACCOUNT licensors. Publishing Rights earlier
  does not repair a later current read or terminal seal under B/C.
- Shared bundle correspondence admits RAW_BYTES/JCS for ordinary payload rows,
  but scoped snapshot and reference rows retain their distinct ABI
  canonicalization identifiers. Relabeling those rows would change evidence.
- Sanction changes live display bytes. The separate public preservation-render
  capability in [ADR 0054](../adr/0054-explicit-non-sanction-preservation-rendering.md)
  requires additive producer and consumer profiles. This existing full-output
  recipe must continue checking the complete live bytes it originally promised.

Fresh browser provenance, complete bundle admission, the original sanction and
archive join, finalization, subsequent currentness, linked bytecode size and
transaction gas remain acceptance work. ABI-only success does not execute these
assertions or prove an EVM transaction fits. Record every eventual result against
its exact source and capture inputs.
