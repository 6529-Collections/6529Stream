# Full-policy publication ceremony fixture

The [current publication fixture](../../test/current/StreamCurrentFullPolicyPublication.t.sol)
authors the actual 37-role graph through STATIC preparation, covered V2 output,
original Artist content-root consent, source snapshot, supplied reference
observations, complete inventory, bundle coverage and the original sanction and
finality calls. This is source integration, not runtime acceptance.

Two concrete constraints remain: the high configured read budgets cannot fit
the 16,777,216 transaction envelope, and live sanction attribution changes the
full JSON committed before sanction. Fresh browser observations, native execution,
normal product sizes and the composed finality path remain unaccepted. No launch
or production-readiness claim follows from this fixture.

## Original authority and ordering

The helper builds the actual current graph and original threshold Artist and
governor Safes. It preserves the accepted foundation policy entries and their
original profile hashes when admitting additional target selectors.

STATIC activation must precede first-release ratification and minting. The new
preparation helper therefore defers the initial two phase configurations through
an additive test hook. Original Manager ownership still transfers to Executor at
the original point. After actual STATIC activation and signed ratification, the
helper records the original phase consents and executes phase configuration and
executor selection through genuine governed calls. Both paid mints use the
original sale, Manager, Core and entropy coordinator. The external randomness
service retains the existing explicit test double.

Original Work/Rights selections, the Artist intent waiver, their seals, STATIC
configuration consent and presentation locks remain real. Core closure, burn
blocking and freezing occur **before** selection and output checkpoints because
the current renderer includes Core lifecycle facts. Separate current-citation
admission uses actual renderer output and independently inserted citation bytes.
Renderer analysis documents remain labelled synthetic fixture evidence; they do
not establish transitive opcode conformance.

The V2 output manifest retains every 640-byte output row and its complete policy
commitments. The original four-field root publication and one-use Artist
operation17 adopt that manifest through Router's existing canonical head plus the
distinct 17-word binding. Snapshot publication uses the actual retained IDENTITY
writer, a SNAPSHOT writer and the original class2 lock authority.

## Full bytes and observation inputs

`exportFullPolicyCurrentSources()` writes the actual Router `tokenHTML` and
`tokenJSON` bytes to `artifacts/full-policy-publication/token-<id>.html` and `.json`.
It checks those bytes against the retained current checkpoint and refuses
`attribution_unavailable`. It never substitutes the old compact/native wrapper.
The artwork is a synchronous 64-by-64 canvas with two token-dependent colors.

`runCapturedFullPolicyCeremonyFromFiles(environmentPath, browserPath,
capturesPath, packageMembersDirectory)` reads explicit observation files and
attempts the whole ceremony. These are Foundry simulation entry points; neither
broadcasts transactions. Use the same frozen source, build, fixture deployment
context and initial chain/time settings for export and replay. Exact-byte checks
reject a changed graph or observation.

The [reference helper](../../test/helpers/StreamCurrentFullPolicyReferenceFixture.sol)
defines the transport:

- Environment JSON supplies `environmentABI`: canonical `abi.encode(Environment)`
  with object, coverage, manifest hash and manifest byte count initially zero.
  Engine, toolchain, viewport, platform and complete file inventories come from
  the supplied observation. Actual archive coverage fills the four fields.
- Browser JSON supplies ZIP identity, size and first/last Arweave endpoint
  witnesses. Capture JSON has `capture1` and `capture2`, identifying the actual
  first/last tokens and Core serials, full HTML/JSON, PNG identities/endpoints and
  two independently observed repeat hashes. Byte fields are hexadecimal strings.
- The member directory supplies `<sourceIndex>.json` for every nonempty package
  member, with original path, identities, byte size and endpoint witnesses. Each
  member must match the environment's exact ordered inventory.

Use the existing [native capture workflow](../../tools/preservation/README.md)
for fresh browser execution and package validation. Its historical V1 reference
manifest validator does not validate the new V2 ABI snapshot. This batch supplies
no fabricated capture report, old-capture substitution or offline V2 acceptance.
Onchain reference checks authenticate the supplied bytes and original archive
records; they cannot prove that an external browser produced those observations.
Archive observer keys and retrieval receipts are explicitly local test evidence.

## Complete preservation and finality candidate

Inventory materialization runs all 31 V2/common definition stages and, for each
token, output, script, library, every renderer row and every current-profile row.
Segment and item totals come from actual retained events. Complete runtime,
schema, source and output bytes are independently retained and matched to the
event digests. Bundle coverage proves each occurrence, including repeated bytes;
package counts come from the supplied inventory instead of historical constants.

The finality helper decodes the genuine provider's complete V2 manifest, checks
all ten original input identities, all nine independent components and every
policy row in the actual source set and snapshot. It then attempts the original
Artist Safe sanction, sanction archive and class2 Registry finalization. The
independent manifest must remain unchanged after sanction; the current source
dependency below prevents calling this an accepted finality flow.

## Sanction changes the checkpoint's live output

The actual display chain is
`StreamArtistRegistryPresentationEncoding.displaySanction` →
`StreamArtistSanctionReads.currentRecord` → the original owner's latest sanction.
It has no finality gate. `StreamStaticArtistReads._sanction` checks that saved
subject, changes the displayed state and records the sanction hash;
`StreamStaticArtistJSON.render` serializes that hash into full token JSON.

`StreamPolicyContentCheckpointV2._current` rerenders every original row through
the current Router and compares its complete hash. Therefore recording the very
sanction required for finality changes the previously committed JSON. Rebuilding
the checkpoint changes the independent manifest and sanction subject again.
This is a source-confirmed dependency cycle; the complete native reproduction
still awaits fresh capture inputs and execution. The fixture keeps the real
unchanged-manifest assertion, rather than removing attribution or weakening
checkpoint validation. Resolving the archival/live-display boundary requires
separate reviewed protocol work.

## Explicit configured budgets

Values below are gas, in millions, used only by the additive ceremony fixture.
Original graph defaults and the existing construction tests remain unchanged.

| Boundary | Fixture cap |
| --- | ---: |
| STATIC attribution | 8 |
| Router marketplace / exported full render / checkpoint render | 16 |
| Checkpoint ordinary read | 6 |
| Output manifest read | 20 |
| Snapshot source read | 24 |
| Reference source / snapshot reads | 16 / 28 |
| Inventory source / snapshot / reference reads | 16 / 32 / 40 |
| Provider component / complete source reads | 40 / 48 |
| Discovery component read | 44 |
| Registry component read | 56 |
| Artist finality read, governed 2→4→8→16→32→64 | 64 |

The policy factory and immutable graph identity reads retain 8m and 12m. These
caps reserve nested calls; they are not measured consumption. For example the
output reader requires **more than 20,417,460** gas before its 20m child call
(`cap + floor(cap/63) + 100,000`), already exceeding 16,777,216 regardless of
the child's eventual cost. Lowering caps safely or staging composed reads needs
real full-output measurements and separate implementation review.
