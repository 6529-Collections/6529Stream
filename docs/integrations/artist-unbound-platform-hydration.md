# Unbound Platform Works hydration

This additive source profile imports original Platform Works collections that have
never had an Artist binding. It supports a registry containing only those
collections and a registry that also contains the ordinary recovered Artist
collections described below. It does not create an Artist, binding, acceptance,
corrective generation, or native receipt for an unbound collection.

The implementation is source/type-checked. Ten actual-producer/Safe scenarios are
authored but have not run. Native templates for the nineteen new libraries fit
across the two bounded captures described below. Capacity of the seven owners and five changed existing
workers, linked-call gas, current-stack execution and deployment acceptance remain
pending.

## Transport and selection

The existing recovered `RH.Request` and operation 60 remain the public entry
points. A selected collection with `artistId == 0` selects the new profile. Every
selected unbound collection must have its actual original Platform declaration,
a completely empty original Binding, no acceptance or attribution generation,
and no policy selector. Ordinary collections retain their authentic Artist IDs.
The entire selected set remains sorted, unique and bounded by the original
aggregate limits. Empty and unrelated subsets do not substitute for complete
source inventories.

The semantic tag is
`keccak256("6529STREAM_ARTIST_UNBOUND_PLATFORM_HYDRATION_V1")`, version 1.
`UNBOUND_PLATFORM` is bit 4194304 in the shared extended-feature vocabulary.
This profile accepts that bit together with the original recovered base bits
0-4 only; its maximum mask is 4194335. It does not set `MULTIPLE_BASE` and does
not extend any old profile's allowed mask. Each of the seven guarded owners
explicitly advertises the new implemented bit. Original RH structures, public
selectors, operation matrices and stored owner roots remain unchanged.

Each owner carries the complete original owner provenance plus a canonical
aggregate semantic row for its actual selected subjects. Owner 4 carries typed
Platform slices; owners 0, 3 and 6 carry empty semantic rows for an unbound
collection and do not install fictitious binding, acceptance or policy state.
These empty rows are meaningful only after full original owner journal,
revision, replay and nonce accounting succeeds.

## Original Platform history

The slice preserves the original twenty-word Platform state, declaration 8,
Platform claim 9, attribution allegation 10, governed contest/dismissal 11 and
an unused governed correction approval 53. All retained claim and contest
bodies, order, counts, latest display claim and exact original replay subjects
survive. An approval must still have corrective generation zero and must not
be accepted. Corrective binding/acceptance and subsequent bound Platform
histories belong to the existing generation profiles and are not silently
reinterpreted as unbound history.

The collector enumerates the actual original Archive catalogues for every
origin and authenticates canonical operation envelopes. Existing Platform
transition proofs check the original actor, payload, governance context and
independent owner-4 before/after revisions. Fields absent from an original
record hash still have to match those Archive bytes. Complete native journals
and replay inventories remain global; per-collection selection never filters
away another subject's provenance.

The writer uses the original typed Platform state writer after the original
empty-destination checks. After all seven owner writes, operation 60 rechecks
the complete source provenance, every relevant original Archive catalogue,
source suite, timing checkpoint and publication inventories before appending
its original evidence and event. A late failure rolls back all owner writes,
lane activation, evidence and the outer transaction.

## Empty principal and repeated imports

A Platform-only registry does not enter singleton Identity preparation. Its
actual original Identity owner must report registration nonce zero, no native
principal journal, no indexed nonce tree and an initialized, unchanged timing
checkpoint whose raw configuration is the original all-zero/default state.
The profile carries a distinct timing checkpoint row, not a zero-Artist
Identity bundle. Governed timing changes on a zero-principal source remain a
separate unsupported composition and are refused.

The original operations 55, 56 and 57 still govern predecessor admission,
collection-lane proofs and one-way cutover. Every selected collection lane is
verified and activated exactly once; no Artist lane is invented. The complete
seven-owner cutoffs and immutable imported prefixes remain mandatory. The
empty-principal validator accounts for each era's actual local lane latches,
cutover and cumulative original import-binding/governance cells. Original
recovered guard handling retains old lane/cutover cells historically without
consuming the successor's future cutover latch. Old import-root/action cells
remain spent. A later claim uses the original successor-domain producer and
continues the original collection history after its imported prefix.

## Initial mixed-registry scope

An ordinary selected Artist must satisfy the complete existing recovered base
profile: supported class 1 or class 3 Identity/Payout history, accepted
generation-one PRIMARY_ONLY binding, base Attribution and direct policy 14.
Its original Identity, recovery, payout, timing, replay, nonce and collection
rows are imported together with all Platform slices. Global registration and
per-owner accounting still cover every selected subject. Ordinary collections
in this first composition must not themselves contain Platform history.

Broader ordinary consent/delegation/attestation histories, multiple generations,
collaborators, bound Platform corrections and other mixed profile combinations
are remaining implementation work. This first composition does not establish
complete Platform migration for every full-v1 history.

## Authored regression scope

The ten new cases cover declaration-only zero-principal import; both original
claim families and governed dismissal; unused correction approval; A -> B -> C with
fresh claims and preserved replay; mixed recovered-Artist import; omission of
an ordinary subject; Archive-only field tampering; missing native/replay rows;
invented timing/nonces; and late Archive rollback with identical Safe retry.
The shared import helper independently recomputes the full original operation-60
commitment and profile hash, checks the single Coordinator event, and immediately
compares the destination public and STATIC display count/latest with the untouched
predecessor. They deploy and invoke the original Artist owners, Archive, history protocols
and Safe. Core, metadata, evidence-coverage and scheduled-governance replies
remain explicit inherited typed fixture boundaries. Inherited old tests are
not counted as new profile executions.

The ABI7 capture contains 1,467 sources and zero type errors. Against
the exact predecessor plus shared feature-recognition dependency, all twelve
modified original products retain their 824 ABI entries, method maps and
recursive storage layouts. These checks are source compatibility evidence,
not native execution, gas, capacity or release acceptance.

## Initial native capacity evidence

The first native Solidity 0.8.19 capture used exact integrated source
`66dc4a308f6a1c1b93187d7295554062d900b5fa`, including the retained Consent
constructor-size repair. It selected only the eighteen new libraries from 508
source inputs, with viaIR, optimizer 200, Paris, and no CBOR metadata. Compilation
completed in 228.557 seconds. Seventeen libraries fit; CollectionRows was 24,987
runtime bytes, exceeding the unchanged 24,576-byte limit by 411 bytes. That
original result is retained.

The capacity successor moves only CollectionRows' replay-alias validator to the
fixed linked `StreamArtistUnboundPlatformReplayRows` library. Its era lookup and
error body are copied exactly. All three call positions, arguments, checks and
error order remain unchanged; there are no caller-memory writes to return. A
whole-file inverse proves the host change, and the host ABI, method identifiers
and recursive storage output remain exact. The original ten test bodies are
unchanged.

The pair-only native successor completed in 29.756 seconds from 509 source
inputs. CollectionRows is 23,981 runtime / 24,014 creation bytes; ReplayRows is
2,778 / 2,810. Both are libraries without constructor arguments. The genuine
outputs retain their own source ASTs, full bytecode fields, source metadata joins
and declared links. These are native template sizes, not independently observed
deployments, measured linked-call gas, or execution of the ten actual scenarios.
The remaining seven owners and five changed existing workers have a separate
finite sizing plan; their capacity has not been inferred from these libraries.
