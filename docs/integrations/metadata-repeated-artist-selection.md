# Original Metadata after repeated Artist migration

The same Metadata host can select an Artist successor after multiple complete
recovered operation60 imports. The original Artist, Metadata address, record hash
domain and consumed publication authorization map remain unchanged. This consumer
does not make an incomplete hydration profile support additional record families.

The original self-selection and single-predecessor path remain. The repeated path
first checks the actual current registry's one immediate history binding, exact
predecessor runtime and completed cutover naming the current registry. It then
reconstructs the original Artist's complete21-word recovery environment from its
pinned original suite: chain, Registry, Coordinator, Archive, all seven owners and
runtime hashes, Core, Manager and original full suite hash. All unchanged
non-Artist suite dependencies must still match the current suite.

The current actual Identity owner exposes an additive imported-only certificate:

```solidity
recoveredHydrationImportedOriginCertificate(bytes32 environmentHash)
    returns (bytes32 originHash, bytes32 importCommitment,
             uint64 importedAtRevision, uint8 ownerIndex);
```

This exact 128-byte response reads the original immutable `originIndexPlusOne`,
origin/era, profile and import fields. The unchanged complete operation60 producer
validates the full environment before installing those fields. Missing keys, local
origins, wrong owner/profile or an absent import fail. The full 672-byte origin
getter and all original prefix bytes remain available; this certificate neither
caches mutable source data nor creates another writer. Its commitment must equal
every one of the seven current owner completion markers.

The current suite remains authenticated against its exact original constructor
hash and all live runtime pins. For repeated selection, one fixed linked worker
then checks the exact immediate predecessor/cutover, original suite and all its
runtime pins, unchanged dependencies, complete original environment hash, current
Router/Core, seven completion markers and imported certificate. Metadata calls
that read-only worker with the unchanged governed dependency budget. The worker
shares that finite STATICCALL frame among these fixed reads and rejects every
failed or incorrectly sized result; it does not reserve the entire budget anew
before each small inner read. Inner source getters are the named original
caller-independent facts, and their caller is this fixed worker. There is no
caller-supplied target or generic batch execution interface. The worker's wire
uses ordinary `bytes` containing `abi.encode(nextSuite)` to avoid Solidity library
struct-selector mangling; it decodes the original typed suite once.

The outer full-forwarding/EIP150 guard is unchanged. At the measured genesis
configuration, the Artist callback is 400,000 gas and Metadata's dependency frame
is 150,000 gas. Neither value nor its floor is raised. This is a finite seven-owner
proof, not an unbounded ancestor walk or a guarantee that arbitrary future source
implementations fit those budgets.

A current successor publication still uses the original Metadata callback and
record domain. An authorization ID consumed before migration stays consumed at
later successors. Fresh publication requires the current Artist's original
publication authorization; ancestry alone does not authorize a record.

The candidate view now validates subject, schema, payload and original candidate
preimage before finishing with Artist selection. Each check is still mandatory.
For inputs with several defects, the first error can therefore change; individual
refusals are tested independently. A failed grouped read is reported against the
fixed worker. The publication mutation still captures selection before candidate
validation and rechecks after append, preserving authorization consumption and
rollback ordering.

The focused successor tests preserve the fourteen original immediate/repeated
recipes and add malformed/missing certificate, source-suite, independently invalid
document/selection and low-budget refusal controls. The repeated cold recipe uses
the actual immutable State producer and actual fixed Owner read worker in a typed
owner boundary; extra stored bindings and a refusal flag add conservative reads.
It cools the named original/current suites, payload and read libraries. Six separate
real Owner probes cover all seven indices, full retained origin bytes, exact
four-word output, local/missing refusal and reached late-failure rollback/retry.

Metadata, schemas, byte store, Safe and fixed read workers are real contracts.
Artist source admission, Coordinator construction and Core/governance remain
explicit typed boundaries. These tests do not execute the full seven-owner
operation60 or prove complete current-graph/cold-transitive deployment acceptance.
Earlier failed selector and gas-reservation captures remain retained separately.

have17 passes and one cold failure, six real Owner certificate probes pass, and
all fifteen original Metadata cases pass (including256 payload fuzz inputs).

The eighteen-product gate on the matched Artist/Metadata source has no runtime
or unparameterized creation-image overrun. Tight runtimes are IdentityWriter24,535,

floor, dependency cap, callback cap, protocol size limit or import authority was
relaxed. The proposed two-frame successor is separately held and unapplied.
