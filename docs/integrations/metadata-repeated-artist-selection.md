# Original Metadata after repeated Artist migration

The same Metadata host can select an Artist successor after multiple complete
recovered operation60 imports. The original Artist, Metadata address, record hash
domain and consumed publication authorization map remain unchanged. This consumer
does not make an incomplete hydration profile support additional record families.

The original self-selection and single-predecessor path remain. The repeated path
first checks the actual current registry's one immediate history binding, exact
predecessor runtime and completed cutover naming the current registry. It then
reconstructs the original Artist's complete21-word recovery environment from its
pinned original suite: chain, Registry, Coordinator, Archive, all seven owners and
runtime hashes, Core, Manager and original full suite hash. All unchanged
non-Artist suite dependencies must still match the current suite.

The current actual Identity owner must return that exact original environment
from its immutable flattened operation60 prefix. The query cannot use its local
origin branch because the original and current registry differ. Only the existing
complete recovered import installs this prefix; a lane proof or an arbitrary
caller-provided origin is insufficient. The enclosing selector still requires
every current owner to expose the same nonzero completion commitment, plus the
original current-suite runtime, Router, Core and chain checks. It does not read
an unbounded history or copy authorization consumption between hosts.

A current successor publication still uses the original Metadata callback and
record domain. An authorization ID consumed before migration stays consumed at
later successors. Fresh publication requires the current Artist's original
publication authorization; ancestry alone does not authorize a record.

Six regression recipes cover all21 original fields, missing provenance, immediate
binding/seal failure, every owner completion, original dependency runtime, chain,
Router, third/fourth successor consumption and the existing400,000-gas candidate
worker. The cold recipe cools the original payload pointer as well as named suites
and libraries. These recipes use explicit typed Artist lineage/prefix boundaries
with actual Metadata, schemas and byte store. They do not demonstrate actual
operations55-57/60 or complete current/Safe execution. Source type checks pass;
native behavior, cold budget and matching deployment sizes remain pending.
