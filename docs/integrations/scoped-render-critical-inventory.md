# Scoped render-critical source inventory

`StreamScopedRenderCriticalInventory` is the distinct staged source producer
for TOKEN, RELEASE and SEASON. It does not implement the COLLECTION interface,
accept a collection receipt for another subject, or make membership into VIEW
adoption authority. It currently consumes the finalized-entropy STATIC profile;
terminal-entropy output needs its separately admitted output and snapshot
profile. The new host and traversal have an ABI/type check only. Their native
execution, size, transaction capacity, complete provider and finality ceremony
remain pending.

## Original source and plan identity

The constructor pins the same named Core, Metadata, Schema, Store, Router,
selection/membership, archive and Artist sources used by its fixed workers.
The snapshot and reference slots name the distinct scoped producers. Runtime
hashes and reciprocal joins are checked at operative reads; predicted late
addresses are not treated as already-live dependencies.

`beginInventory(scope)` derives its context from the actual current scoped
reference, complete snapshot and membership, authoritative scoped CONTENT_ROOT,
WORK/RIGHTS, and conservation selection. The plan domain is
`6529STREAM_SCOPED_RENDER_CRITICAL_PLAN_V1`, followed by chain, actual inventory
host, dependency hash and the complete context. Repeating the same current plan
returns its existing ID without another event. Callers do not supply the
source context, expected token count or segment list.

Each mutation refreshes that complete current source before its stage runs.
Evidence already completed remains readable historically; `requireCurrent`
requires the exact current context and active interpretation documents.
Permissionless preparation confers no publication, Artist, archive or finality
authority.

## Complete ordered traversal

The public interface is `IStreamScopedRenderCriticalInventory`. Its fixed order
is:

1. `appendNative(id, maximum)`: next 1–64 original native source/runtime rows.
2. `appendReference(id, maximum)`: next 1–64 reference rows, including every
   original package member, declared platform prerequisite and capture.
3. `appendWork`, then `appendRights`: exact selected typed records and bytes.
4. `appendIntent` or `appendIntentWaiver`, then `appendInterview` or its actual
   parent-bound waiver: the original selected conservation evidence.
5. `appendRootAuthorization`: original op17 Archive proof. Historical aggregate
   and legacy-family values are untrusted preimage witnesses, authenticated by
   the original scoped record and signed family state.
6. `appendDefinition`: every fixed required definition, in the producer's order.
7. For every authoritative membership ordinal, `appendTokenOutput`,
   `appendTokenScript`, `appendTokenLibrary`, every `appendTokenRenderer` row,
   then every `appendTokenCitation` row.
8. `sealInventory`: only after all source stages and every token's final row.

The token phase and row cursor are available through `tokenProgress(id)`.
There is no caller-selected next ordinal or expected row total. A token advances
only after its output, executable bytes, renderer evidence and optional current
citation evidence finish. Script and library workers verify every original
logical chunk plus the complete ordered payload; empty/absent declarations
remain explicit occurrences. Full output uses the checkpoint's exact current
`tokenJSON` and `tokenHTML` selectors, with the finite profile bounds of 65,536
JSON, 40,960 HTML and 2,048 image bytes. Larger outputs are not silently truncated
or accepted as complete.

Native/reference totals come from the authenticated original records. A small
segment limit never turns a capture sample into complete membership or a partial
ZIP member list into complete environment evidence. Token ordinals retain Core's
actual global token ID, permanent collection serial and burned lifecycle; they
are not converted to serial plus one. Empty/incomplete membership refuses this
reference-dependent profile.

## Current citation evidence

An original renderer without the capability contributes one explicit ABSENT
occurrence. A capable renderer must have the separate, actual current-base-
citation admission. The inventory includes its complete 12-word registration
record, exact superset of the original read declarations, actual registered
analysis/golden bytes, and pinned encoding runtime. It independently rebuilds
the original read-set and registration hashes and checks the exact profile,
selector, chain, Schema registry and saved original version.

The complete original renderer target roster and its original five documents
remain mandatory separate rows. Current citation evidence does not replace
those original goldens or create terminal-entropy admission. Actual selected
renderer/citation document facts are deduplicated by document ID and rechecked
at sealing and current reads, including status changes; repeated occurrences
still remain in the ordered inventory itself. Full-byte diagnostics reconstruct
the same retained definitions.

## Evidence and limits

Each segment key uses `6529STREAM_SCOPED_RENDER_CRITICAL_SEGMENT_V1`, plan ID and
actual sequential segment index. Every original occurrence enters the existing
ordered item/link chain. The completed evidence uses
`6529STREAM_SCOPED_RENDER_CRITICAL_EVIDENCE_V1`, chain, actual host, dependency
hash and the full scope/evidence tuple with its evidence hash still zero.
Original eight record coordinates, full membership hash/count and complete
segment chain/count enter that tuple. Historical getters do not require current
source eligibility.

The coherent 560-source ABI check includes this host, fixed stages, the scoped
provider and combined profile Discovery. Four token/source
cases and six current-citation cases are authored; none have been run natively
in this scoped batch. The citation tests use actual Membership, Metadata, Schema
and Store, with explicit typed Core, Router/output, Registry and Renderer
admission boundaries. Those tests do not establish governed renderer admission,
an actual current Core ceremony or a fully sealed inventory.

This source producer does not prove archive coverage, independent analysis,
browser/metric execution, opcode conformance, or full finality acceptance.
The fixed scoped archive coverage/provider consumers are implemented in this
batch; their actual complete positive source flow, size and runtime acceptance
remain required. Scoped PERCEPTUAL/CURATED modes and VIEW
adoption retain their distinct required authority and evidence work. All
COLLECTION records, selectors and domains remain unchanged.
