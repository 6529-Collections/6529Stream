# Recovered multiple-Artist base hydration

## Status and supported graph

The distinct **MULTIPLE_BASE** feature bit **262144** extends the existing
recovered operation60 request to a complete graph with more than one Artist or
collection. All seven concrete owners advertise the additive capability. The
existing singleton masks and codecs retain their meanings; the Coordinator,
Registry selectors, operation masks, signature domains and storage layouts are
unchanged.

The first aggregate profile carries complete recovered class1/class3 Identity,
Payout, guardian, rotation, estate, dormancy, recovery preparation/execution,
timing and nonce histories supported by the original recovered base validators.
Each selected Artist must have an actual retained recovery. Every selected
collection must have an accepted generation-one, no-collaborator PRIMARY_ONLY
binding in consent mode1, base Attribution and complete direct operation14 policy
history.

The aggregate rejects all retained delegations, even unused grants, and rejects
economics, sale/content/freeze/ratification records, operation24, corrections,
multiple generations, disputes, collection sanction history and Platform history.
Those families remain supported where their existing singleton codecs admit
them. Aggregate combinations are subsequent feature batches; capability
availability does not turn them on here. Collaborator and class4 authority remain
outside this profile.

Nine actual-owner scenarios are authored and pass Solidity0.8.19 ABI/type
compilation. They have not executed. Native behavior, joined current-stack
capacity, transaction gas, fuzz/invariant and release acceptance remain pending.
The inherited Core and scheduled-governance fixtures are explicit unit
boundaries; Registry, seven owners, Coordinator, Archive and threshold Safes are
actual products.

expected identifier.

The fixed dispatch selects this profile only for multiple Artists or
collections. One Artist and one collection still enter the unchanged original
preparation and singleton guard. Omitting scopes does not select a smaller valid

## Complete conservation

Admission authenticates the governed predecessor, actual cutover and verified
lanes once. Every native occurrence remains in its complete original owner
journal, with its original environment, native index and owner revision.
No filtered or renumbered provenance is created.

Binding, Acceptance and Consent count all selected rows against complete
owner/era checkpoints. Binding and base Attribution retain two mutations per
accepted proposal. Proposal and acceptance share an original era. Replay aliases
cover every relevant original guard in every later era. Zero-history
Collaborator and Attribution constraints remain explicit.

Identity rows use the original native, recovery, guardian, authority, document
and auxiliary validators over full provenance. The source's genuine
action-to-Artist getter resolves every preparation alias to a selected Artist.
Global document/signature maps preserve identical-content sharing and reject
conflicting content. Repeated secondary35 hashes remain distinct occurrences.

The aggregate nonce entry changes only the singleton cardinality assumption:
local principal/rotation/estate lanes form an exact disjoint union of the one
global inventory. It compares kinds, keys, all prefixes and32 words, exhaustion,
and original index order, retaining genuine hints. Original tree installation
and first-unused hint checks remain. Delegation/collaborator kinds reject.

Every authentic bundle agrees on the complete timing bundle and global
registration counter. The counter equals the complete original registration
inventory; current authority addresses must be distinct. Timing and that
counter install once, then each principal's original heads, records,
continuations and artifact points. The fixed aggregate principal worker differs
from the original by separating the shared counter write. The fixed nonce
worker takes the globally ordered lane array; its tree installation body is
unchanged.

Preparation runs its source prelude once. A fixed typed owner helper then builds
all seven complete payloads and calls the original inventory seal in the same
frame. This internal frame boundary preserves the complete owner-loop order and
final seal while avoiding a nested seven-owner return decoder.

Payout retains original per-Artist codecs and Identity joins over complete
source provenance. Every external action, finality and entropy observation
enters the aggregate snapshot and is rechecked after writes.

## Atomic operation and historical meaning

Every owner receives exactly one original guarded apply, one complete provenance
and replay import, one publication catalog and one final revision increment.
Each unique Artist/collection lane activates once through the existing
multiple-lane helper. Its historical commitment domain remains unchanged; the
complete recovered value binds the new feature and schema.

Import neither reauthorizes old signatures nor creates original native receipts.
Original domains, bytes, clocks, source checkpoints and publication carriers
remain unchanged. The common commit rechecks source checkpoints, suite, timing,
publications and external observations, then creates paged Archive evidence.
A late failure rolls back every selected scope and owner.

## Authored regression coverage

The actual-owner cases cover:

- One recovered Artist and two accepted collections with direct policies.
- Two recovered class1 Artists with shared document bytes and guardian Safe,
  distinct nonce trees, and repeated secondary35 hashes at original positions.
- Mixed class1/class3 estate/recovery imported through a threshold Safe.
- Repeated imports with complete original owner journals unchanged.
- Late Archive failure for direct and Safe calls, rollback and identical retry.
- Omitted/duplicate scopes, stale inventory, excluded witness families, an
  authentic unused delegation grant and unchanged singleton selection.
- Missing, foreign, modified or duplicate nonce lanes; changed words/exhaustion,
  registration counter, timing and first-unused hint.

Source/type checks and selected capacity measurements are separate from
execution evidence. Existing singleton scenarios remain required regression
coverage in the joined native campaign.
