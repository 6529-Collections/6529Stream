# Scoped reference observations

`StreamScopedReferencePublication` records the bounded `BYTE_EXACT` reference
profile for TOKEN, RELEASE and SEASON. It has its own immutable deployment,
interpretation documents and record domains. It does not reinterpret original
COLLECTION records or reuse their content roots. The new deployment belongs in
the supplemental product/dependency inventory; it is not hidden behind an
existing genesis address.

The original scoped Snapshot supplies complete authoritative membership,
ordered selection and content/output commitments, locked Artist presentation
and the complete original entropy source inventory. The Router must already
have adopted that exact snapshot through its scoped `CONTENT_ROOT` publication
path. That path retains original operation-17 Artist consent. A scoped
reference publisher neither grants nor substitutes for that authority.

## Publication and retained bytes

The constructor pins Core, Metadata, schemas, immutable Store, Router, scoped
Snapshots and external artifact coverage with their exact runtimes and chain.
It verifies the original Metadata governance binding and registers four
governed read budgets. Current source validation rechecks the actual snapshot
configuration, current snapshot bytes and current Router root before accepting
an observation.

`previewReference(publication, recorder)` and `publishReference(publication)`
use `StreamScopedReferenceTypes.Publication`: a complete scope plus the
original typed observation fields. The observation's collection ID must match
the scope. The actual Metadata `CURATOR` family grants authorize publication:
class 3 at that collection, then class 8 at scope zero. The chosen nonzero
grant revision and original caller enter the receipt. A preview is a read,
not a claim that the same computation fits a transaction.

Prepare the original Environment using the existing file-inventory and
environment preparation companions. Full rows retain their original IDs and
canonical JSON. Upload the complete preview payload and `abi.encode(publication)`
to the fixed Store in chunks of at most 8,192 bytes. Set the preview's exact
source hash in `observation.expectedSourcesHash`, then publish as the same
authorized recorder. The producer recomputes the live source hash and refuses
a stale or caller-invented value. It retains full bytes through the original
Store manifests, rechecks its writer grant and scope lineage, then appends.
Missing bytes or a later failure roll back all publication state.

These immutable original bytes remain accessible through `referenceRecord`,
`referencePayload` and `referenceSource`. Scope-keyed `referenceCount` and
`referenceAt` retain every historical occurrence; `currentReference` identifies
the head. Historical byte access does not assert that the original source is
still current. `requireCurrent` separately recomputes current source facts and
checks the complete original payload commitment.

The first and last observations are selected by authoritative membership
ordinal, with one observation when both are the same token. Each token's
collection serial, lifecycle and original coordinator come from Core. Serial
is never inferred as ordinal plus one. Burned tokens retain their historical
identity and original entropy facts. The producer checks the exact saved
STATIC Renderer/version/runtime selection, output row, complete token data,
current historical Router JSON and embedded HTML. Both observed PNG SHA-256
values must agree and match authenticated archive coverage. Runtime ZIP and
image object format/schema identities are separately checked. Samples are
not a substitute for the complete render-critical archive inventory.

## Scope locks and provider reads

`lockTransition(scope)` derives an exact action scope and old/new state.
`lockReference(scope)` requires the pinned original Executor's class-2
`currentAction` for those values and revalidates the current reference. It
seals the head once; further publication for that scope refuses.
`finalityStateForScope` returns the exact scoped reference component only when
that same current head has its original lock. It does not claim to implement
the collection-only component selector.

`StreamFinalityScopedReferenceReads` is the fixed consumer for a provider's
constructor-pinned graph. It verifies reciprocal source configuration,
canonical full record encoding, the complete original record hash and every
scope/receipt/definition join. Its current read calls the original validating
host; its locked read and component projection verify the exact scope-keyed
class-2 receipt and component hash. The provider cannot supply an arbitrary
per-call source or borrow a COLLECTION reference for another subject.

The closed definitions are
`schemas/records/STREAM_SCOPED_REFERENCE_RENDER_ABI_V1.json` and
`schemas/records/STREAM_SCOPED_REFERENCE_RENDER_PROFILE_V1.json`, with constants
in `StreamScopedReferenceDefinitions`. Original registered definitions remain
unchanged. Distinct Keccak domains identify scoped sources, payload, record,
chain, lock action and terminal component. Scope IDs use the original canonical
Metadata subject rules. Empty or incomplete membership cannot manufacture a
reference sample or readiness claim.

## Current evidence and remaining composition

The host, fixed consumer and seven authored cases pass the 174-source ABI/type
check. The tests use actual Membership, inventories, Metadata, Schema, Store,
scoped Snapshot, the new reference host and official threshold Safe. They retain
explicit typed Core, Artist, Renderer/output, Router-root, archive and governance
boundaries. They have not run natively or passed a selected product-size gate.
No browser capture, current-Core ceremony, transaction-capacity or transitive
renderer-conformance result is implied.

The complete scoped provider, complete render-critical inventory/archive join
and actual finality ceremony remain required. Scoped PERCEPTUAL_TOLERANCE and
CURATED_EQUIVALENCE need their own full scope-bound mode/context/evidence
admission; this BYTE_EXACT producer does not promote collection mode evidence.
VIEW remains a distinct required profile with exact selected view payload,
Renderer and Artist adoption authority. Membership alone cannot authorize it.
