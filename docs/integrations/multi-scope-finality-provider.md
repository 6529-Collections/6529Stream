# Combined finality provider source

`StreamFinalityMultiScopeEvidenceProvider` joins the existing native COLLECTION
provider and distinct TOKEN, RELEASE and SEASON producers at one selected host.
Its ten selected host/worker products fit the original size limits. Complete
integration and runtime validation remain pending. It is not a deployment or complete full-v1 acceptance claim.

The original COLLECTION operations execute the original `super` bodies using
the new deployment's address. No prior provider identity, receipt or accepted
record transfers to this host. Original COLLECTION configuration, schema and
hash domains remain unchanged. The separate `StreamFinalityPolicyMultiScopeEvidenceProvider` adds distinct
COLLECTION policy V2 dispatch; see [profile Discovery](profile-finality-discovery.md).
VIEW still needs an actual selected/adopted view source and is not treated as
this scoped profile.

## Fixed source configuration

The constructor accepts the original native 22-role configuration and the
scoped 22-role configuration. Only roles 8/9/18/19 differ: scoped snapshot,
scoped reference, scoped render-critical inventory and its complete bundle
coverage. Shared addresses, runtime pins, chain and gas budgets must match.
Every value is nonzero and stored only in construction. Predicted late
dependencies are checked for real runtime, exact configuration and reciprocal
bindings on operative reads. Constructor completion is not source readiness.

The new `IStreamScopedContentRootEvidenceBinding` exposes the actual scoped
snapshot address, runtime pin and validation budget to the original Router.
The Router still owns CONTENT_ROOT consent, replay and publication authority.
`IStreamFinalityScopedMetadataReads` exposes root/snapshot/manifest by the full
scope tuple; callers cannot substitute a bare scope ID or COLLECTION payload.

The separate COLLECTION V2 configuration additionally replaces role 10
with the actual V2 policy source factory. Its source set must be created by
that factory. A V2 source-set address is not a factory, and the old factory
cannot construct the new source-set profile.

Scoped Metadata facts require the actual selected WORK/RIGHTS seals, intent
lock, canonical scoped root, membership and original class-2 snapshot lock.
An open collection need not be globally frozen to freeze an admitted token or

These local facts do not recurse through input manifests or component arrays.

Manifest/input/sanction operations use the fixed scoped workers, complete
current inventory and exact bundle coverage. Registry-only prepared operations
