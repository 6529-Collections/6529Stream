# Native personhood documentary references

This additive profile connects the original Artist operation-24
personhood head to an exact original General identity notarization. It provides
checkable documentary linkage for AA-IDENTITY 8, CMC-ATTESTATIONS 11 and
CMC-MUSEUM-GRADE 2(f). It does not establish legal personhood, institutional
standing, instrument validity, or factual truth. Signer verification and those
external trust questions remain distinct.

The implementation has source and test-oracle review plus a 2,630-source
Solidity 0.8.19 ABI/type/storage check. Original production ABI entries and
recursive storage layouts are preserved. The 28 behavioral cases are authored;
execution, contract size, transaction gas and complete current-stack acceptance
remain pending. This is not complete Museum acquisition evidence.

## Original selection authority

The original `recordArtistAttestation` operation is the only fresh selector.
Use subject kind 10, the actual primary Artist ID, its operative identity record
hash, and the unchanged `6529STREAM_ARTIST_PERSONHOOD_EVIDENCE_V1` schema.
Original op24 signatures, nonce guards, authority classes, native record hashes,
events, owner commit and Archive transaction boundaries remain unchanged.
`StreamArtistC2PACredentials.note`, already called inside op24 and complete op60
imports, retains the derived proof in the same transaction. There is no new
external owner mutation, independent selector, signature, or nonce.

The statement is the separately pinned, closed 590-byte JSON interpretation
generated by `StreamArtistPersonhoodJSON`. Its eight ordered keys bind original
Artist Registry, Artist ID, operative identity record, General host/runtime and
record hash, profile hash, and version. Existing native statements and hashes
are not rewritten. An old opaque evidence statement stays historical and has
status UNRESOLVED; a later C2PA credentials record does not replace, satisfy,
or erase this schema-specific personhood head. Explicit waiver behavior remains
the original election.

Register the exact new interpretation document as CATALOG name
`STREAM_ARTIST_PERSONHOOD_REFERENCE_JSON_PROFILE_V1`, using original Schema
Registry governance, RAW_BYTES canonicalization, and supersedes zero. Its source
is `schemas/records/STREAM_ARTIST_PERSONHOOD_REFERENCE_JSON_PROFILE_V1.json`:
1,837 bytes including LF, Keccak-256
`0x06eaf449a0abe6a4305706d589bc597f14f7d23f62acc661b4b1fff128b921c3`.
Do not replace any previously registered schema/profile under its original ID.
The original notarization schema, JSON profile, and RFC8785 definitions are
independently checked against their original literal hashes and full bytes.

## Full proof at recording

A canonical new reference requires the actual Core-selected Module Registry,
an ACTIVE General module of original type/version/interface/runtime, reciprocal
Core and Artist Registry pins, and the issuer's exact selected notarization
head. The proof reads the complete original General record/receipt, original
subject tuple, payload, signature bundle, receipt inventory position and schema
definitions. It independently rebuilds the original record and authorization
preimages. It requires the original institutional/estate signer-verified
notarization family and exact original identity Registry/Artist/operative
identity facts; a generic self-assertion or native Artist-labelled statement
cannot substitute.

Collection, token and media subjects use the original `StreamIndependentReads`
constants and field order. No invented subject domain is introduced. The
original producer verified the signature when the immutable receipt was
recorded. This proof preserves that recorded result; it does not call today's
ERC1271 owners to reauthorize an old signature or infer an issuer's external
institutional standing.

After full verification, a 48-word immutable `Summary` binds the native record,
statement, Artist, original Registry/code, binding/generation/collection,
operative identity, reference, Core/Module/Schema/Store pins, immutable document
facts, exact report head key, documentary hash, module identity and six retained
carrier/code hashes. The six carriers are report payload, signature bundle and
the four exact single-chunk definitions. The native record's summary hash is
`keccak256(abi.encode(keccak256("6529STREAM_ARTIST_PERSONHOOD_PROOF_SUMMARY_V1"), summary))`.
An additive event and original payload-store carrier retain this documentary
preimage for reconstruction. Neither is a new authority record.

## Bounded currentness versus documentary audit

Read the actual fixed Attribution owner selected by the normal Artist
Registry/Coordinator suite. This capability adds no Registry facade selector.

| Method | Contract |
| --- | --- |
| `personhoodEvidence(collectionId,artistId)` | Original native head, retained reference/provenance, live status and head facts. |
| `personhoodEvidenceStatus(collectionId,artistId)` | Compact original native hash and the same status for the prospective floor. |
| `personhoodProofSummary(nativeRecordHash)` | Immutable validated summary; zero version means none. |
| `personhoodProofSummaryHash(nativeRecordHash)` | Independently retained hash, checked against stored summary bytes. |
| `auditPersonhoodEvidence(nativeRecordHash)` | Full documentary replay and original hash comparison, separately from mint currentness. |

Currentness rechecks the actual owner/suite, current accepted binding and
generation/hash, current operative identity, original Registry/Core/General/
Module/Schema/Store runtime pins, all six immutable carriers, actual current
Module Registry pointer, General catalogue identity/lifecycle, original document
facts, and the same recorder-scoped General head. It never follows a newer head.
It never copies a mutable payload into a trusted cache. Full documentary data
was validated once at original op24 and remains behind immutable producer,
schema and carrier identities. The full audit deliberately rereads those bytes.

The compact serving path uses the existing raisable ARTIST_SALE_FACTS_READ_GAS
row, including its original failure class and full EIP-150 forwarding precheck.
Full admission/audit/import uses the existing ARTIST_FINALITY_READ_GAS row.
No cap, floor, gas default or caller-controlled allowance is raised here. Cold
execution within the original Manager/Artist budgets is unmeasured and remains
a required post-approval test; avoiding repeated documentary replay is an
architecture choice, not a numerical gas claim.

| Status | Meaning |
| --- | --- |
| NONE | No native personhood head. |
| WAIVER | Original explicit waiver remains current for actual identity/generation. |
| RESOLVED | The exact admitted documentary summary remains current under all bounded joins. |
| STALE | A prior admitted record has a known identity/binding/head/lifecycle/definition/code mismatch. |
| UNRESOLVED | Opaque legacy data, missing proof, or malformed/unavailable bounded reads. |

DEPRECATED permits inspection of immutable prior documentary evidence; it does
not admit a fresh reference. INCIDENT_REVOKED and unknown modules cannot supply
RESOLVED status. Known mismatches retain the original selected evidence as STALE;
failed reads are explicit UNRESOLVED. There is no hidden fallback to another
notary, recorder, native head or later credential record.

The prospective Museum floor is intentionally stricter: evidence-schema heads
must return their exact native hash with RESOLVED status, or the existing
explicit waiver must apply. Historical opaque evidence does not establish the
checkable identity notarization required by CMC-ATTESTATIONS 11 / CMC-MUSEUM-GRADE
2(f). Original record getters, retained bytes and historical acceptance facts
are unchanged; this proposal does not retrospectively claim that old floor
checks verified documentary linkage.

## Original domains across migration

Complete authenticated operation60 imports retain original native and General
Registry domains. The original journals, record hashes, nonce/replay history,
owner headers, complete supplied rows and one-shot all-seven-owner transaction
remain the import authority. For each canonical evidence row, the fixed importer
locates the actual original Registry's Coordinator and Attribution owner through
reciprocal immutable suite facts and copies that owner's exact summary and
retained hash. It independently joins native record, statement, Artist,
collection, binding, generation, operative identity, original reference and
Core/runtime pins before storing anything authoritative. The existing op60 guard
must already be installed; there is no alternate summary writer.

Missing capability, absent summary, malformed encoding, changed hash, foreign
Registry/Artist/collection or substituted identity is a whole-import refusal,
not a false empty head. Opaque legacy and waiver rows stay their existing
historical profiles without inventing proof. Supported old typed row encodings
and original hashes do not change; the new derived namespace is mandatory for
canonical evidence and is atomically retained with its original owner data,
payload tail and Archive. Any late source or Archive failure rolls all of it back.

An imported original General record can remain inspectable in its original
domain after Artist cutover. A fresh successor op24 must name the successor's
own Registry domain and a genuine notarization admitted for that identity
configuration; it cannot promote the imported old reference into fresh authority.

### Rollback and retention oracles

The 28 authored cases include distinct op24 and op60 late-Archive failures.
The op60 case uses the actual Archive uint64 block bound and requires exactly two
append calls across the failed attempt and identical successful retry. The retry
alone cannot satisfy this counted expectation. The append is after all seven
owner imports. A separate missing-row early-refusal control requires exactly one
append across its refused attempt and completed-input retry, proving that this
early failure is not counted as a late Archive attempt.
It compares all seven checkpoints (including nonce/replay roots and counts),
hydration commitments, native receipt counts, history activation commitment,
personhood selection and summary, Identity/Attribution/Consent/Archive payload
counts, source state and Safe nonce. After restoring the block, it submits the
exact same target calldata through the actual Safe and requires the seven
matching nonzero completion commitments. Reverted inspector observations are
not treated as durable logs; only successful retry logs are folded.

Fresh recording and completed import independently reconstruct the tagged
summary ABI bytes and require one `ARTIST_PERSONHOOD_PROOF_SUMMARY` catalog row
in both the actual Attribution owner and Archive. The two catalogs must name
the same immutable carrier with exact STOP-prefixed length and code hash.
The successful `ArtistPersonhoodProofRetained` event must have the actual owner
emitter, original native record and Registry topics, schema version, summary
hash and every complete Summary field. These assertions fail if the new summary
retention or event is removed while the older documentary carriers remain.

`testFuzzCanonicalJsonRoundTrip` is a same-codec roundtrip fuzz recipe, not an
independent differential implementation. The fixed profile bytes, native and
summary preimages, catalog/event checks and malformed-input controls are separate
oracles. These cases remain unexecuted; gas, capacity, current-stack and full
acquisition-conformance acceptance are not established.

The late-failure test counts both Archive attempts. A successful retry alone
cannot satisfy the assertion; the separate early-refusal control expects only
one attempt. Both tests still require execution against the fitting joined graph.
