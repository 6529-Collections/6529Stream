# Adopted VIEW preservation inventory

This additive profile inventories the original adopted VIEW and every member's
complete preservation output. It does not reinterpret COLLECTION, scoped-V1 or
COLLECTION policy-V2 receipts. Permissionless preparation grants no Artist,
publication, archive or finality authority.

The current implementation is source-authored and type-checked. Its 30 new test
recipes are authored, not executed: media correspondence (4), actual reference
and output projections (7), inventory state/preimages (6), VIEW archive
coverage with the original actual Archive/Safe fixture (7), and typed source
selection reciprocity (6). ABI56 checks 293 source files with zero errors.
The first 18-product size gate fits 16 products; the 30,413-byte NativeReads
and 29,048-byte SourceReads results are retained. Their exact retained-read and
staging bodies are now in fixed workers; the successor size gate is separate. Complete positive inventory assembly and the
combined provider/Registry/Discovery ceremony remain required. The previous
46-case output checkpoint result does not execute these new inventory methods.

## Original sources and complete order

The host pins `StreamRenderCriticalSourceTypes.Dependencies` (1,344 ABI bytes).
Its twelve targets remain Core, Metadata, Schema, Store, Router, snapshot,
reference, WORK, RIGHTS, conservation selection, whole-byte artifact coverage
and external coverage. Targets 5 and 6 are the distinct VIEW snapshot and
reference publishers. The five Artist coordinates and Content owner remain
explicit constructor pins.

Every append and final seal rechecks the complete current VIEW reference,
snapshot, adopted declaration, policy roster, signed CONTENT_ROOT, WORK,
RIGHTS, conservation and exact Artist association. The plan binds the entire
typed context, chain, actual host and dependencies. Its stages are:

1. Original snapshot/root/adoption/source/policy bytes, all runtime dependencies,
   every full covered output part and its complete index.
2. Original reference record/payload, full environment and archive observations.
3. WORK and RIGHTS records, then intent, interview and their applicable waivers.
4. Actual original Artist op17 CONTENT_ROOT authorization and retained Archive
   evidence, including the authenticated historical aggregate preimage.
5. All 36 fixed interpretation definitions.
6. Full adopted declaration, immutable payload, script and image obligation.
7. Actual selected Renderer registration, read set, target catalogue, source
   bindings, encoder, policy binding and five documents.
8. Actual governed preservation registration, complete read/target catalogue,
   fixed producer/worker/encoder bindings and three admission documents.
9. Every membership ordinal's actual token/collection serial/lifecycle,
   tokenData, full 31-word output row, complete JSON and HTML, and original
   at-mint Coordinator runtime.

The twelve internal stage numbers distinguish WORK from RIGHTS and each shared
closure above. The token count is complete membership, not the reference
capture count. Each output is observed again and compared with every saved row
field. Historical burned-member serving remains explicitly discriminated.
Selected Renderer/admission document pins are deduplicated for currentness,
while every ordered inventory occurrence remains in the segment chain.

Snapshot and reference `ORIGINAL_PAYLOAD` inventory rows preserve their exact
original schema IDs, whole canonical payload bytes, length and Keccak digest.
Their archive correspondence is `RAW_BYTES`, as for any complete byte carrier;
the original publication receipt's canonicalization hash and complete schema/
canonicalization documents remain unchanged. The shared Archive reader is not
widened to accept arbitrary ABI canonicalization claims. The focused Archive
case uses genuine archive observations of the fixture's original bytes; it
does not mislabel those bytes as a VIEW publication.

The original collection/scoped contracts and byte domains are unchanged.
The new inventory profile is
`keccak256("6529STREAM_VIEW_PRESERVATION_RENDER_CRITICAL_V1")`.
The new bundle profile is
`keccak256("6529STREAM_VIEW_PRESERVATION_BUNDLE_IMMUTABLE_STOP_AGGREGATE_V1")`.
Inventory evidence is 736 bytes; bundle evidence is 288 bytes. Both include the
full canonical VIEW scope. A caller-supplied hash or a prepared segment is not
an accepted current inventory.

## Image URI correspondence

The exact adopted URI bytes are always an inventory occurrence. An empty image
is explicitly absent. A canonical lowercase `ipfs://b` CIDv1 with raw codec and
SHA-256 multihash authenticates the file digest; the CID alone does not establish
size or availability. The original bundle proof must establish a nonzero full
byte length and actual current archive coverage for that digest.

The pre-genesis draft now also admits two closed locator obligations under the
same explicit VIEW inventory and sanction-review profiles. This changes the new
draft source and exact sanction catalogue bytes; it does not update a registered
document in place. A deployment must register the exact new bytes and obtain
fresh admission. Earlier captures, including the raw-CID-only composed tests,
remain evidence only for their recorded source.

An exact `https://` locator must pass the original Archive institutional ASCII
DNS/path grammar (10–2,048 bytes) and equal the complete retained identifier of
the same covered object's signed institutional receipt. A canonical `ar://`
locator contains exactly 43 unpadded base64url characters encoding a nonzero
32-byte transaction ID, with zero trailing bits and no path/query/fragment. It
must equal that same pair's endowed receipt identifier; the original native
checkpoint binds the transaction, data root and full byte size. Neither URI is
interpreted as a file digest.

These rows use `EXTERNAL_REFERENCE`, role `VIEW_ARCHIVE_LOCATOR_IMAGE`,
`RAW_BYTES`, algorithm zero, empty digest and unknown size zero. Their provenance
is `keccak256(abi.encode(keccak256("6529STREAM_VIEW_ARCHIVE_LOCATOR_OBLIGATION_V1"),
source, sourceRecord, exactURI))`. All other optional coordinates remain zero.
The complete inventory source, ordered row and its original archive Admission
are still committed separately. The fixed VIEW reader reconstructs the entire
canonical row, reads the actual object, validates original complete receipt,
fixity, native evidence and current pair, then checks exact locator equality.
A separate temporary row supplies that authenticated object's digest to the
unchanged generic Archive reader; retained locator rows remain unchanged.

The same fixed reader serves cover, refresh, full-current diagnosis and media
review. Locator evidence requires external backend 1. Raw CID and absent rows
retain their exact original bytes and generic correspondence behavior. No
caller-selected profile or object digest can bypass these joins.

Arbitrary origin HTTPS URLs that differ from the signed institution locator,
redirects/mirrors, Arweave subpaths/manifests, DAG-PB CIDs and other unsupported
URI forms still require a real retrieval-correspondence witness. Original VIEW
payload admission does not admit inline data URIs. These remain visible required
completeness work, not omitted media or inferred package-file correspondence.
See [the bounded locator guide](view-locator-correspondence-v1.md).

## Once-bound complete source selection

`IStreamViewPreservationFinalitySourcesV1.Selection` contains exactly six words:
reference publisher/address runtime, render-critical inventory/address runtime,
and bundle archive coverage/address runtime. `viewFinalitySources()` returns
192 bytes. The 416-byte receipt additionally commits the three initial
dependency hashes, original basic binding record, same class2 action, bound time
and its own record hash.

The combined provider owner binds this selection together with the existing
seven-word VIEW configuration and original declaration in one class2 action.
Basic-only and complete binding share the same once-only guard. Either first
binding permanently closes both entry points; complete-finality getters must
refuse a basic-only bind. This interface does not introduce a second mutable
selection or change existing COLLECTION/scoped configuration commitments.

The complete proposal/receipt domains belong to the combined provider's typed
complete-binding implementation. Consumers must use that exact committed
implementation rather than invent a second hash recipe from this interface.

The fixed `StreamFinalityViewPreservationSourceSelectionV1.requireBindings`
accepts the six-word `Selection`, a 37-word typed `Expected`, and `readGas`.
It returns the three full current dependency hashes. `Expected` contains twelve
targets/pins, five Artist targets/pins, Content owner/pin and chain. The combined
host derives these only from its authenticated original inventory dependency
tuple/hash and original mappings/Artist graph, replacing roles 5, 6 and 10 with
the actual bound VIEW snapshot, reference and artifact coverage. Caller-supplied
coordinates do not establish that authority.

At binding, check actual nonzero runtime pins, exact canonical ABI/capabilities
and these reciprocal identities, without requiring unpublished current roots:

Reference gas parameters remain governed. The binding receipt retains the
initial dependency hashes and basic receipt/action linkage. The operative
`viewFinalitySources` getter reruns `requireBindings` for current identity,
runtime, canonical dependency and reciprocal checks, without requiring its
returned current dependency hashes to equal those historical hashes. Actual
finality separately requires full current evidence. A later permitted gas change must not
be mistaken for a new publisher selection. Inventory and bundle constructor
dependencies remain fixed storage.

Finality must independently obtain the actual current snapshot/reference and
their required class2 locks, current inventory evidence, complete current bundle
coverage, metadata/Artist predicates and original Registry admission. The
selection getters alone establish none of these conditions.

## Capacity and freshness boundary

Parts contain at most 64 ordered full rows; all parts and the covered complete
index are required. The original 16,384-member scope limit and 524,288-byte
carrier bound remain unchanged. Final checkpoint/currentness re-observes every
member. Small-scope execution cannot establish a 16,384-row transaction fit.
No complete monotonic invalidation aggregate exists across all mutable output
producers, so this implementation does not replace those reads with a staged
source-context equality shortcut. The separate immutable-STOP archive refresh
profile does not establish VIEW output freshness.

For the current source-integration diagnostic, the new inventory gas tuple is
`(read=2,000,000, source=18,000,000, selection=8,000,000,
snapshot=18,000,000, reference=24,000,000)` and the new bundle tuple is
`(read=2,000,000, archive=8,000,000)`. These are constructor parameters for the
new products, not changes to existing producer caps. They deliberately make no
16,777,216-gas transaction claim: forwarding a 24-million reference read cannot
fit that envelope, and the original strict nested reader reserves remain.
The original reference's 16-million snapshot read alone needs more than
16,263,968 gas at that call boundary, before the other currentness work.

An actual small complete VIEW sanction path with measured cold work and valid
constructor budgets remains required. The Artist's existing governed
`ARTIST_FINALITY_READ_GAS` parameter can be raised only through its original
delayed at-most-twofold actions; changing that forwarding ceiling is not proof
of an executable sanction within the unchanged transaction cap. Complete
maximum-scope capacity remains separately open.
