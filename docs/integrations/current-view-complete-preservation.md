# Complete VIEW preservation source binding

This recipe extends the [current VIEW ceremony](current-view-preservation-ceremony.md)
with a complete fixed source selection and exact-subject documentary records.
The implementation and cases are source-authored. ABI checks and source review
do not establish execution, transaction capacity, browser provenance or finality.

## One governed binding

The same four-argument combined provider offers an additive complete binding:
the original seven-word configuration, original declaration binding and six-word
selection of reference, inventory and bundle hosts. All three actual hosts are
deployed before the one original class-2 action. No current root, observation or
inventory is required at this construction stage.

Basic and complete binding share one guard. Either first bind permanently closes
both entry points and both previews. A complete bind records the original basic
receipt and a distinct complete receipt atomically, with the same action and
timestamp. Governance authorizes the full proposal, including all three initial
dependency hashes. It never executes a separate inner basic proposal.

Expected source identities come from the provider's authenticated original
inventory configuration. The complete validator checks the exact original
twelve-role and five-Artist rosters, Content owner, runtime pins, capabilities,
profiles, chain and reciprocal producer identities. Only the selected VIEW
snapshot, reference and snapshot artifact-coverage coordinates are substituted.
A caller cannot supply the expected roster.

`viewFinalitySources()` revalidates those identities and reciprocities. The
historical receipt getter verifies the stored commitment and original basic
receipt linkage; runtime drift does not erase historical admission. The receipt
retains initial reference gas values. A permitted later reference gas change
does not constitute selection of a different publisher, so operative validation
does not compare today's full dependency hash with that initial hash.

## Genuine records and inventory

The VIEW subject is registered from its actual original membership record before
any documentary append. The fixture then creates separate VIEW Work and Rights
records, an original Artist op24 intent waiver with an explicit interview waiver,
class-2 description locks and an Artist Safe intent lock. This occurs before
checkpointing. Original COLLECTION records, payloads, selections and locks remain
addressable and unchanged.

After supplied reference observations are published and locked, the inventory
helper traverses every stage and ordered member. It reconstructs the exact
schema-versioned segment events, item links, counts and evidence preimage. It
retains complete actual source bytes, including JSON, HTML, runtime code,
definitions and original records. Archive coverage uses actual chunked onchain
artifacts, original object receipts and original Artist state bundles. Nonempty
package members require explicit matching archive endpoint witnesses.

`runSuppliedViewInventoryObservation(environmentJSON, browserJSON, capturesJSON,
packageMembersDirectory)` is an external observation entry, not a default test.
It reuses the three hosts fixed by the original complete bind. It neither runs a
browser nor supplies synthetic default observations. The authored artwork has an
empty image field; it does not demonstrate external-image archive acceptance.

## Original provider and finality ceremony

The combined provider dispatches VIEW catalogue, component, manifest, review,
prepared-input and metadata reads to the fixed VIEW kernels using its original
constructor configuration. VIEW dispatch precedes the older scoped selector.
Both prepared-input methods first authenticate the original Registry address and
runtime. The complete binding receipt selects producers; every operative finality
read still requires the relevant current evidence.

`runSuppliedViewFinalityObservation(environmentJSON, browserJSON, capturesJSON,
packageMembersDirectory, measuredArtistReadGas)` extends the explicit observation
entry through the original sanction and scoped finalization. It constructs the
same complete graph, publishes the supplied observations, materializes the full
inventory and covers its bytes before preparing the ceremony. It then registers
the original four sanction definitions and the exact VIEW input/schema/media
definitions supplied by the fixed producers.

The source recipe obtains nine sorted independent components and the provider's
non-sanction manifest, prepares exact VIEW terms and signs original Artist op12
with the actual Artist Safe. It archives the original sanction bytes, obtains
the ten-component set and executes original class-2 scoped finality through the
Root Safe. Readback joins the stored components, execution action and archive
witness. Preservation JSON/HTML and the independent manifest must remain stable
while the live sanction display changes.

`measuredArtistReadGas = 0` retains the original allowance. A nonzero target must
come from separate measurements; the helper applies only original delayed,
at-most-twofold class-1 raises with exact state readback. Its 16,777,216 ceiling
is a diagnostic guard, not a whole-transaction capacity result. The authority
regression's 3m input tests governance behavior and is not a measured target.

This supplied-observation entry has not been executed. It supplies no browser
defaults and does not establish observation provenance, external-image support
for this empty-image fixture, gas capacity or completed finality acceptance.

## Diagnostic budgets and remaining acceptance

The new hosts use explicit constructor configurations:

| Host | Constructor gas tuple |
| --- | --- |
| Existing VIEW reference profile | read/source/snapshot/archive: 1m/16m/16m/1m |
| New VIEW inventory | read/source/selection/snapshot/reference: 2m/18m/8m/18m/24m |
| New VIEW bundle | read/archive: 2m/8m |

These are diagnostic source/integration configurations. They are **not** evidence
of acceptance under the 16,777,216 transaction limit. Existing host budgets are
not mutated by complete binding. Necessary nested-call reserves do not establish
the total work fits. Measurements must determine viable small-scope budgets.

The original Artist sanction allowance begins at 2m and remains governed through
its existing monotonic, at-most-twofold class-1 gas transition. Any increase for
the later ceremony must follow measured need, exact governance and readback.
High-budget provider previews do not prove that the real Artist signing callback
or executed finalization fits.

Executed inventory/archive closure, sanction, finalization and combined
acceptance remain required. Original
`confirmSanctionFinalized(uint256)` is COLLECTION-only. VIEW evidence alone does
not confirm a COLLECTION sanction or change collection attribution; genuine
separate COLLECTION finality can satisfy its own confirmation rules.
